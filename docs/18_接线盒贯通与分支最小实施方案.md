# 接线盒贯通与分支最小实施方案
日期：2026-10-13
状态：可执行方案，待实施

## 1. 要解决的情况

用户已确认原图有两种情况：导线在接线盒两侧断开，分别接入盒内或接线位置；同一回路在接线盒处分成多个支路。

处理结果统一为：接线盒参与连接，继续追踪全部支路；接线盒不计入负载数量、功率和灯具材料表，同一个灯具按实体句柄只统计一次。保持原图导线和图块不变。

## 2. 最小实现选择

只增加一种角色 `junction`，中文显示为“接线盒”，复用现有图块接触判定、邻接表和队列追踪。不要新增端口编辑器、自动猜测配线功能或独立连接引擎。

分类复用当前图纸配置的 `roles`、`EL:PutRole` 和 `EL:SaveConfig`，不另建配置文件，不写入公共设备库。角色记录仍使用既有的 `identity / role / confirmed` 结构，只扩展允许的角色值。

增加一个简单命令 `ELJBOX`：

1. 默认操作为“设置”，拾取一个或多个接线盒图块样本。
2. 按固定回路流程使用的图块身份记录为 `junction`，同类型实例自动适用；不要求逐个接线盒拾取。
3. 命令打印实际应用的块型名称，保存当前图纸配置，提示重新运行 `ELSTAT`。
4. 提供“取消”操作，移除所选块型的接线盒分类，恢复现有默认识别规则。
5. Esc 取消本次操作，不覆盖此前保存的配置。只在完成选择后一次性保存。

首版沿用固定回路流程已有的块型身份口径，不新增动态状态分类系统。仅用于同一身份确实都是接线盒的块型；同名混用为灯具等其他对象时，不得整类设置。

## 3. 连接和追踪规则

### 3.1 两侧断线贯通

每个接线盒实例作为一个连接节点，导线通过真实端点接入它：

- 端点接触图块有效几何，或者位于已有几何模块能够确认的真实封闭区域内，即认定接入。
- 复用端点接触的既有容差和高程检查，不引入新的距离参数。
- 包围盒仅作粗筛，不能因为端点落在包围盒内就认定接入。
- 单纯从接线盒中段穿过、端点在盒外的另一根线，不作为该盒的新接入线；本身连续的导线仍沿原路径追踪。
- 接线盒与其他图块的轮廓接触，不自动建立图块之间的连接。

连接关系示例：`导线 A → 接线盒 J → 导线 B`。只在内存邻接表中增加 `A-J`、`J-B` 两条边，不在 DWG 中补线，不通过 2000 mm 自由端续接来模拟盒内连接。已接入接线盒的端点应标为占用，避免再次参与自由端跨接。

同一个盒内接点若还被原导线端点接触逻辑识别为导线直连，只保留通过盒节点的连接表达，避免重复边形成三角而误报闭合；盒外真实导线连接不删除。

有两个有效接入导线时贯通；有三个及以上时按分支继续；只有一个有效接入导线时，显示该盒连接未完整并定位到盒，不把本回路宣称为完整。看得见间隙但不满足既有接触规则时，也不能扩大接线盒范围强行吸附。

### 3.2 同一回路分支

`EL:TraceCircuit` 到达 `junction` 时遍历全部邻接导线，使用已有 `visited` 去重，接线盒本身只加入回路对象集合，不加入 `devices`。

接线盒邻接数大于 2 是正常分支，不产生 `ABNORMAL_BRANCH`。遍历后的灯具仍按句柄去重，并汇总到原出口回路；不为每个支路生成新的回路编号。真实闭合线路沿用既有闭合检查，不能为了允许分支而关闭所有异常判断。

### 3.3 防止合并独立回路

首版只支持一个接线盒实例内部属于同一回路的情况，不解析盒内多个独立接线组。

整箱分回路后，检查所选出口回路之间是否共用了接线盒或导线对象。发生共用时，显示涉及的回路及接线盒位置，标记这些回路归属冲突，阻止它们作为完整统计结果生成系统图，不自动合并、不按先后访问顺序分配。共用检查必须在排除接线盒负载和用户排除设备之前执行，不能只依赖 `devices` 的冲突检查。

导线只是从盒附近经过或者交叉，不满足端点接入规则，就保持原有独立关系。

## 4. 按现有入口实施

| 修改位置 | 必须完成的最小改动 |
| --- | --- |
| `src/config.lsp` | `EL:RoleShape` 允许 `junction`；实现 `ELJBOX`，复用现有图纸配置保存和块型身份 |
| `src/simple.lsp` | `EL:SimpleNetworkBuild` 对已登记接线盒保留 `junction`，其他图块维持原规则；接线盒只建立导线端点接入边，跳过涉及接线盒的图块互接边；端点占用与候选范围包含接线盒 |
| `src/panel.lsp` | `EL:CircuitSnapshot` 不把 `junction` 覆盖成 `device`；分回路后在出线选择结果上检查共享接线盒或导线，修改出线选择时重算冲突 |
| `src/topology.lsp` | `EL:TraceCircuit` 允许经过 `junction`，支持多支路，不把它加入负载集合；仅豁免接线盒的正常多邻接分支判断 |
| 统计和来源复核调用处 | 核对所有负载入口仅使用真实设备；分类变更参与识别规则与缓存失效判断，保存重开和重新识别使用同一分类 |

建网与生成快照必须使用同一个角色解析辅助函数：所选配电箱优先为 `panel`；配置中明确登记的接线盒为 `junction`；其余图块保留当前默认规则。固定流程使用的身份须与 `ELJBOX` 写入的身份一致，避免保存成功但建网查不到分类。

当前 `EL:CountRows` 已只统计 `device`，应优先利用这一条件；设备库准备、功率表、材料表也不得从全部图块重新把接线盒加入负载。接线盒无需填写 `0W`，不作为缺少功率的设备报错。

现有 `EL:ApplyDeviceExclusions` 只排除统计设备，不能代替接线盒分类；不要把“取消接线盒”混入“恢复排除”。

回路编号继续使用原出口身份，不因接线盒分支重新编号。编号范围中的图块首次接触边界沿用现有口径，接线盒连接问题不扩展成编号算法重写任务。

当前 `EL:SimpleNetwork` 缓存键已包含配置，分类变化可使建网缓存失效；还须将分类写入识别规则版本或相应签名，使旧保存结果触发正常重新统计。`EL:RecognizeFixed` 和 `EL:FixedFreshSnapshot` 必须读取相同图纸配置，不能只在交互统计时识别接线盒。

## 5. 必要验证和交付

只增加以下定向用例，不为本功能扩展全面回归：

1. **贯通**：箱体 → 导线 → 接线盒 → 导线 → 两个灯具；两个灯具都识别到，接线盒不计数量和功率。
2. **分支**：一个接线盒接一条来线、两条支线，支线分别有 2 个和 3 个灯具；结果为原回路 5 个灯具，不报正常分支异常。补查同一灯具被多个线段命中只计一次。
3. **不误接**：另一根线从盒中段穿过但端点在盒外、端点仅落在包围盒空白处、不同高程三种情况，都不新增接线盒连接。
4. **归属和异常**：两个选中出口实际接到同一个盒时报告冲突；单端盒连接不完整；真实闭合线路仍报告原有问题。
5. **保存恢复**：保存重开仍贯通且不计盒负载；取消分类恢复默认规则；Esc 保留原配置；分类改变后旧识别结果不能继续被视为有效。

源码实施时，按项目约定重新执行 `tools/build_cad2020.py`，使用下一个可用三位序号，并检查解压目录和 ZIP 内全部 LISP/DCL 的严格 GB2312 解码及内容一致性。源码、必要测试和文档按任务路径提交；交付包及生成目录精确忽略。

真实 AutoCAD 2020 验收使用用户这张原图：执行 `ELJBOX` 登记接线盒后重新运行 `ELSTAT`，高亮应到达盒后的灯具及全部支路，核对灯具数量与功率，保存重开复核；接线盒不进入灯具负载表，原导线和图块未被改写。自动用例通过不能替代这项原图验收。

本方案阶段仅新增文档，不修改 LISP/DCL，不生成交付包。
