# 性能优化 P0：命令计量与日志对照 091
日期：2026-10-11
状态：计量已实现，177 项针对性检查与完整交付验证通过；真实 AutoCAD 2020 基线待采集

## 本阶段范围

以 `feaa40b` 的最新源码和 090 功能为实施前版本，091 加入计量，不改变识别、布局、持久化格式和精确回读规则。059 是方案中的历史参照，057 日志也仍保留历史身份；未取得相同环境的历史版本样本前，不计算与 059 的提速百分比。

ELSTAT、ELGEN、ELUPDATE 每次顶层命令保留一份性能汇总，内部切换保存记录或多次打开日志不重置计数。已有 ELTRACE／ELPOWER 日志会话也能采样。成功、取消和错误路径均收尾，事务内捕获的错误先结束未完成计量区间，再继续撤销，不将撤销后执行时间算入鼠标等待。

正常业务日志仍默认开启。新增 ELPERF 仅供性能诊断，在本次加载会话内调整日志对照和计量详略，不写入 DWG 或配置文件。没有在统计面板增加“快速／安全”选择。

## 加载与采样操作

1. 完整解压 `应急照明-091.zip`，APPLOAD 包内 `START-CAD2020.lsp`，确认显示 v91。保留整个目录，加载文件已由构建脚本严格转换为 GB2312。
2. 运行 `ELPERF`，默认是汇总计量和业务日志开启。需要明确恢复时，分别输入 `Summary`、`LogsOn`；直接 Enter 保持当前设置。
3. 在同一机器、同一 AutoCAD 2020 版本和相同 DWG 状态下，分别采集四回路原位更新、完全无变化更新，以及五条实际回路加两条预留的首次放置。首次放置与原位更新分组，不能混算。
4. 每组预热一次，再恢复相同 DWG 基线副本，执行至少五次有效运行。每次命令只处理一个来源箱体并提交一次，然后结束命令；命令内多次提交的汇总只用于诊断，不纳入单次生成的基准组。按既有面板入口打开保存记录，核对后点击“生成或更新”。
5. 记录机器、CPU、内存、CAD 版本、DWG 样例名称与规模、场景和运行序号；核对回路数量、功率、预留和定位结果。保留命令行显示的 `ELPERF.log` 路径及正常 `ELTRACE-debug.log`。若从嵌入启动文件建立了本地运行目录，记录位于该目录的 `output` 中。
6. 运行 `ELPERF` 输入 `LogsOff`，按同样步骤重复同一组对照。`ELPERF.log` 独立保留；该模式停止业务日志行格式化及落盘，调用方提前构造的上下文仍可能执行，因此差值不能解释为所有诊断相关计算的总成本。错误阶段和上下文仍可从命令行取得。
7. 对照结束运行 `ELPERF` 输入 `LogsOn`。主要阶段需要细查时才输入 `Detail`，另建细分组采样，完成后恢复 `Summary`；汇总组与细分组分别比较。

## 记录字段与解释

每条记录采用 `PERF | <AutoLISP 数据关联表>`，一条顶层命令一行，不截短数据。无法写入插件目录时尝试 `TEMPPREFIX/ELPERF.log`；仍失败时将汇总留在 `*EL:PerfLastSummary*`，性能输出失败不改变业务返回值。

| 字段 | 含义与边界 |
| --- | --- |
| `package`、`command`、`status`、`last-outcome` | 包标记、顶层命令和结束状态；`command-finished` 仅表示命令结束，不自动证明生成成功，仍核对业务结果、事务失败数和原日志 |
| `total-ms` | 顶层命令开始到收尾汇总前的总区间，包含交互；性能报告自身格式化与文件写入不包含在内 |
| `interaction-ms` | DCL 停留、拾取、预览后 Enter、确认输入及原生拖放等交互区间的并集；嵌套区间不重复相加 |
| `program-ms` | 总区间减去上述交互区间；DCL 回调计算和原生插入自身处理可能包含在交互区间内，不能把它当作精确 CPU 时间 |
| `after-submit` | 最后一次主面板确认到顶层命令收尾的总区间及排除交互后的程序区间；多次提交时不代表每次提交的平均值 |
| `after-placement` | 最后一次原生插入返回有效箱体，或非原生路径接受插入点，到命令收尾的总区间及程序区间；原生标记位于动态属性、实际布局和关联准备之前 |
| `stages` | 采集、建网、识别、存储读／解码、提交、诊断导出、定位等阶段的调用次数、包含耗时、排除交互耗时和父阶段；它们存在包含关系，不能相加当作总耗时 |
| `recognize-fixed-calls`、`store-read-calls`、`store-write-calls` | 实际完整识别和主记录接口调用次数，读取统计包含写后回读触发的读取 |
| `entity-write-attempts`、`entity-write-returned` | 受管输出创建、设置属性、移动、关联 entmod 和删除等写接口尝试／正常返回次数；正常返回可以是 nil，不代表写入成功；不包含事务标记、模板探针或图层表维护 |
| `master-write-attempts` | 进入实际主 XRecord 创建／替换的次数；与纯读取及写前校验区分 |
| `wire-count`、`block-count`、`actual-circuits`、`reserve-circuits` | 最后一次识别／生成计划中的样例规模；`store-payload-fields` 是最后一次编码字段数，`store-entry-fields` 还包含读取到的 XRecord 元数据，两者不混用 |
| `transaction-starts`、`transaction-failures` | 新事务与被捕获失败的次数，用于排除失败或撤销样本 |
| `log-open-attempts`、`log-write-attempts`、`log-close-attempts` | 业务日志文件操作次数，不包含独立性能汇总自身的文件操作 |
| `detail` 及细分指标 | 按需启用签名、回路追踪、实际实体创建、关联、撤销边界及日志行构造／I/O 耗时；不对每个顶点或对象追加性能日志 |
| `metrics` 中的 `clock-available` | `MILLISECS` 是否可读；不可读的记录不能作为性能基准 |

发生取消或错误时，未正常返回的阶段标记 `interrupted`；汇总保留其已执行区间，但不把该记录当作成功基准。记录写接口尝试数的目的是暴露无效重复写入，写后正确性仍依赖原有精确回读和撤销检查。

## 检查与下一步

检查入口为 `python -X utf8 tests/run_performance_checks.py`，复用实际 LISP 的存储、更新、面板、事务和加载检查，新增合成时钟、日志关闭后的独立报告、零写入计数和取消收尾检查。有限适配器及合成时钟只验证计量逻辑，不能给出真实 CAD 的提速结果。

本次共 177 项通过，其中新增计量检查 12 项。原编号样例补齐输入后复测；记录保留完整检查与失败用例复测的历史。`--retry-failures` 仅供修正测试输入后使用，生产源码或构建脚本改变后必须重新执行完整针对性检查。

091 解压目录与 ZIP 的全部 20 个 LISP/DCL 文件通过严格 GB2312 解码和字节一致性检查，其中 19 个 LISP 通过语法解析；性能说明和检查 JSON 已随完整包提供。

真实基线采集完成后，按主要阶段耗时、调用次数、改动风险和依赖确定 P1、P1a、P2 顺序。详细字节量、模板去重及变更集合的基线在对应阶段开始前补齐。P2a 的精简、迁移与兼容回退仍单独实施；本次不根据适配器运行时间宣称 CAD 瓶颈已经定位。
