## 1. 目标与已确认的交互

用户手工使用天正 `HLBH` 完成平面回路编号。程序在拾取配电箱并提取独立出线回路时读取这些编号，使主面板与系统图采用相同的显示编号。平面尚未标号的回路继续按现有顺序自动显示默认编号。

读取时机固定在：**出线识别完成、恢复稳定回路身份及排列顺序之后，主面板显示之前。** 每次重新提取、重新统计或更新来源时重新读取；不增加逐条拾取标注的步骤。

编号搜索范围为每条独立出线从配电箱边界到首个已识别设备之间的导线。多根导线拼成该段时逐根检查；分支分别在各自遇到的首个设备处停止。设备之后的其他导线标号不参与本条出线编号的选择。

本功能只读取平面原生对象的数据，保存本程序的统计与系统图关联。功率、设备、地面设置、箱体容量、模板布局、实际回路顺序和预留数量沿用现有规则。编号变化不改变回路身份。

原 `HLPLBH` 批量点击工具及 [09—12 历史方案入口](09_天正HLBH批量回路编号工具方案.md)保留，不接入本功能。用户反馈该工具仍未通过 CAD 实测；本方案转向读取已经完成的原生标注，不继续模拟 HLBH 点击，不以 `TextString` 是否公开作为读取编号的前提。

[08 同箱多平面补充拾取方案](08_同箱多平面独立回路补充拾取方案.md)仍是另一项待实施工作，本次不增加补充拾取或多来源合并功能。将来接入时复用本方案的编号解析与逻辑配电箱内去重规则。

```lisp
;; 标注 6B67 的扩展数据
(-3
  ("TG_DIMWIRE_TYPE" (1000 . "WireNameOnly"))
  ("KeyOwnWireId" (1000 . "KeyOwnWireId") (1005 . "2227")))

;; 导线 2227 的扩展数据
(-3 ("linenum" (1000 . "ZE1")))
```

本样本证明：`标注 6B67 -> 导线 2227 -> 编号 ZE1` 的数据读取路径成立。`TG_DIMWIRE_TYPE` 和 `KeyOwnWireId` 内的其他字符串不是编号；`330` / `OwnerID` 是所属对象关系，不作为导线关联字段。`HasExtensionDictionary = 0` 不影响这里已经读出的 XData。

正式识别从出线导线直接读取 `linenum`，不需要全图扫描标注。上述句柄只作样本，实施不得硬编码 `6B67`、`2227`、示例图层或坐标。句柄必须结合当前图纸和真实实体数据核对；运行时图元名不作为持久身份。

该证据只覆盖一组原生对象，没有证明多回路界面、系统图生成、改号同步、复制、保存重开或其他天正版本已经通过。用户输出末尾重复的 `-3` 是 `foreach` 表达式返回最后一个打印值形成的重复显示，不应据此构造两个 XData 组。

## 4. 首段范围与原生编号读取规则

### 4.1 确定首段

1. 以当前回路种子和真实箱体轮廓为起点，确定导线离开箱体的方向；集中干线入口沿用已有逻辑箱体边界。多接触点或方向无法区分时记录歧义，不按距离选一端。
2. 在已经确认的连接网络中按路径方向前进。断线续接只使用现有已接受的自动续接或人工配对；图面交叉不直接视为连接。
3. 对每根源导线按段或曲线行进顺序检查真实设备接触，复用现有轮廓、孔洞、宽导线和容差规则；包围盒仅作候选筛选。先遇到设备就结束该方向的编号搜索。
4. 分支发生在首个设备之前时，检查各支路到各自首个设备的范围；汇合处去重。同一首段内取得多个编号仍须合并校验，不在首次发现编号时提前放弃其他候选。
5. 遇到首个设备后，全回路的设备识别、功率统计和路径预览继续运行。编号搜索的结束不截断原回路统计。

一根长多段线可能同时覆盖设备前后，`linenum` 归属于整根实体。只要这根实体属于唯一独立出线且经过其首段，允许读取它的编号；不据此声称已经读出标注的几何落点。设备后的其他独立导线不加入首段。

虚拟切分段必须通过 `source-wire` 还原来源并去重。若同一个源实体被多个独立出线共用，仅有实体级 `linenum` 无法区分各段归属时，报告编号来源歧义，不能把一个编号自动分给多条回路。

首段边界无法确认时保留问题及定位依据，不能伪装成“平面未标号”。已有无设备、断线歧义或归属冲突的完整性检查继续生效。

### 4.2 读取与解析

对首段每个不同的真实源句柄进行一次定向读取：

```lisp
(entget entity '("linenum"))
```

解析器遍历 `-3` 组中的应用节点，匹配 `linenum`，读取其 `1000` 字符串；不假设字段位置固定，不把其他应用的数据当成编号，也不将整段结果转成打印文本再搜索。

| 读取结果 | 处理 |
| --- | --- |
| 无 `linenum`，或可读取的字符串去除首尾空白后为空 | 记为正常未标号，允许自动编号 |
| 取得唯一有效非空编号 | 候选编号来自平面，保留完整文字 |
| 多处得到同一个编号 | 合并为一个候选，保留全部来源证据 |
| 同一首段得到不同编号 | 回路编号冲突，列出候选和来源 |
| 实体失效、接口报错、结构异常或应用内没有可解释的字符串字段 | 读取异常，不能按未标号掩盖 |

保留原编号的大小写、前缀、中文、连字符和数字位数，例如 `ZE1`、`WL1`、`ALE(JZ)-ZE1`。比较时只去除首尾空白并采用统一大小写比较；`ZE01` 与 `ZE1` 不做数值合并。内嵌换行或格式控制片段必须报告，不擅自删改源值。长编号在详情或命令行中完整显示，持久化及系统图文字不得截断。

首段仅正常无编号时才能自动补号。下游孤立标号、其他箱体相同标号、标注文字与导线的最近距离，都不作为补充编号依据。

## 5. 排序、默认号与冲突处理

先完成 `EL:MatchCircuits` 并保留其 `output-order`，再在最终面板顺序上分配显示编号。读取到的平面编号不触发重新排序，既有 UID、功率、地面选择和设备归属均保留。

分配规则固定为两遍：

1. 收集本逻辑配电箱所有实际回路的有效平面编号，先做同箱去重。不同箱之间允许使用相同编号；同箱不同 UID 使用相同编号属于冲突，不自动改号。
2. 按最终显示顺序处理无标号回路。第 `i` 行先尝试原默认号 `ZEi`，已被平面编号或先前自动号占用时依次向后递增，直到可用。

| 最终回路顺序上的平面编号 | 实际显示编号 | 说明 |
| --- | --- | --- |
| 无、无、无 | `ZE1、ZE2、ZE3` | 完全沿用原默认逻辑 |
| `ZE3`、无、`ZE1` | `ZE3、ZE2、ZE1` | 原回路排列顺序保留 |
| `ZE2`、无 | `ZE2、ZE3` | 第二行原默认号已占用，向后避让 |
| 无、`ZE1` | `ZE2、ZE1` | 两遍分配先保护后面的平面编号 |
| `WL1`、无 | `WL1、ZE2` | 原生自定义前缀保留；默认前缀仍沿用原逻辑 |
| `ZE1`、`ZE1` | 两行保留冲突提示 | 不改写任一平面标注，也不自动重命名 |

本版自动号按当前顺序确定，不承诺在增删回路后自动号永远不变；内部 UID 才承担持续关联。历史自动号不能覆盖本次新读到的平面编号。读取来源清空后重新提取的回路按当前自动规则处理，不继续冒充平面编号。

预留数量沿用 `EL:FixedOutputCount`，本功能不改变模板容量或预留策略。面板仍显示现有“预留1”等用途文字；系统图预留编号按原行位置生成，并避开全部实际编号及已分配预留号。预留行不读取 `linenum`、不计设备及功率。

编号冲突、异常或首段歧义允许继续查看统计与编辑功率，也可保存带问题状态的草稿；正式生成和更新已有系统图必须等待问题解决。草稿保存不得使旧系统图被标记为已同步。问题显示于现有面板提示区域，给出完整候选编号和源句柄，复用现有定位/预览能力；不增加正常流程的确认弹窗。

## 6. 数据、保存与复核合同

建议新增以下字段，实施不得改变既有身份字段含义：

| 层级 / 字段 | 内容与约束 |
| --- | --- |
| 回路 `circuit-number` | 最终显示字符串；行内多号尚未解决时为空，不用任意一个候选冒充结果 |
| 回路 `number-source` | `plane`、`auto` 或旧记录兼容时的 `legacy` |
| 回路 `number-status` | `ready`、`conflict`、`invalid`、`path-ambiguous`；同箱重号可保留读取值但状态为冲突 |
| 回路 `number-evidence` | 首段真实源句柄、候选编号、边界设备及必要的路径依据 |
| 结果 / 记录 `number-policy-version` | 本版为 `1`，区分编号策略，不混入几何续接规则版本 |
| 结果 / 记录 `number-inputs` | 每个首段源实体的定向 XData 原始结构及读取状态；无编号实体也必须记录 |
| 计划 / 正式行中的编号字段 | 与已确认回路一致，供系统图标注创建、原位更新和回读核对 |

正常 `ELSTAT` 路径在 `EL:PreparedResult` 完成身份恢复和排序后调用统一编号解析/分配。复用同一结果准备路径的集中干线、保存记录重开和 `ELUPDATE` 都需要获得同样的规则；独立 `CCKK2` 未传统计结果时保持原默认编号。

保存及更新要求：

- 草稿、正式行和生成计划携带同一编号及来源；`EL:RecordRows` 目前按字段白名单复制，必须显式补充新字段，不能依靠内存中存在就宣称已保存。
- 旧记录无编号字段时按原行顺序显示默认号，并标明兼容来源；正常重新提取后以当前源数据为准。不得通过旧 `R1`、显示编号或功率重新匹配 UID。
- 沿用 DWG XRecord、类型编码及完整回读校验。新增业务字段不擅自改动 `EL_TYPED_V1` / `EL_COMPACT_TYPED_V2` 的线格式，也不额外建立一套平面标号数据库。
- 只改编号时按 `circuit-uid` 原位更新对应系统图编号文字；保留箱体、回路块、用途文字、功率文字、人工位置和地面设置。平面标注及导线不写入、不分解。
- 编号与图形修改继续纳入既有事务；失败完整恢复记录和受管输出，不能报告部分同步成功。

**编号复核与几何签名分开。** 首段计算完成后收集 `number-inputs`，不把编号字段混入断线人工配对所依赖的几何签名，也不因单纯改号递增 `box-policy` / `gap-policy` 使原配对全部失效。

`EL:FreshResult` 保留既有几何复核，另外定向回读 `number-inputs` 涉及的源句柄，并精确比较原始结构和读取状态。几何已改变时沿用现有重新统计要求；几何未变而编号新增、改动或清空时，仍须阻止按旧面板内容生成，提示重新提取。初次未标号的源实体也在复核集合中，确保后加平面标号能被发现。仅下游其他导线编号变化，不影响本功能的编号复核集合。

本版不增加常驻监听。每次重新提取重读当前编号，历史记录显示保存时的快照；打开历史箱体进入编辑时执行当前识别/准备流程。一次复核阶段内按源句柄去重读取，不能复用上次命令的编号缓存；保留 `EL:FixedFreshSnapshot` 不重新追踪全回路的优化。

若天正改号或删除标注后不维护导线的 `linenum`，必须将该真实验收项标为未通过并补充该版本适配。当前只读数据不能自动证明屏幕上的私有文字仍等于 `linenum`，不能将陈旧元数据当作已验证的显示同步。
