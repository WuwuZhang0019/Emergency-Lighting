## 3. 上述问题的待实施解决方案

### 3.1 减少重复模板检查

1. 每个 DWG、每组实际块定义维护有效样本句柄；先验证已知句柄的所属图纸、类型和有效块名，避免每次遍历全图找同一块。
2. 只有块定义、没有可用实例时，在必要的校验范围内共用一次临时探测结果；临时对象必须清理，不能把被删除探针的句柄留作有效样本。
3. 同一受控阶段共用已核对的定义数据、动态属性和允许状态，避免面板确认、输入保存、生成入口连续重复读取。
4. 跨用户交互、未知回调、切图、重载、UNDO/REDO 或相关定义变化后失效并重新核对；不能单凭相同名称、相同范围或 DBMOD 判断未变。
5. 保留同名同范围内部几何改变的拦截，保留写后回读。不能通过删除必要校验来换取速度。

### 3.2 候选采集、网络准备与编号

现有代码已有图层筛选、部分块名复用和几何懒加载，不把这些描述为新的待实现收益。

- 候选 ID 去重中反复使用线性 `member`，可改为命令内索引，同时保留原始对象顺序和全部候选。
- 继续细分原生实体读取、导线几何构造、范围读取、空间树构建、候选去重和贴临设备扩展，按实测选择下一项。
- 保留沿导线的真实接触与贴临设备链；不能用任意空间窗口裁掉远端、断口候选或相邻设备。
- 编号范围复用相同点、线段和轮廓的判定；不减少既有二分次数，不放宽毫米级容差。
- 优先级随样本变化。上一轮真实连接搜索仅 0.562 秒，新复杂设备样本必须重新判断，不能固定沿用历史排序。

### 3.3 首次箱体放置与放置后处理

分别计量进入原生插入命令、可移动预览、用户确认、动态属性切换、模板复核、计划重建、源图核对和各回路创建。44.531 秒的原生区间须与用户操作区分，不能全部作为可消除程序时间。

放置后的 8.125 秒中，仅已确认源图核对为 1.156 秒。先拆清其余约 6.969 秒，再决定是否优化动态状态切换、重复模板检查或计划重建。正常主流程仍只在放置前保存一次输入；全部图文完成后保留必要事务收尾，不恢复二次主记录保存、自动导出、全图重生成和自动缩放。

用户选择的是系统图输出块来源，不是平面设备识别范围，也不是让用户选择是否跳过可靠性校验。

## 5. 计时、实施与验证边界

先补轻量批次计时：样本查找、定义读取/比较、动态属性、图库打开、块复制、样式复制、模板采集、生成计划及动态状态切换；按钮动作开始时间必须与较晚的提交标记分别记录。

拟实施顺序为：明确计时边界 → 根据最新样本确定热点 → 减少模板重复工作与增加来源选择 → 候选/编号优化 → 必要的原生插入优化。新复杂设备问题补入后，可调整实际优先级。

每阶段只运行与改动有关的必要对照，不默认执行全量测试或构建。识别结果、设备归属、回路编号、功率、预留数量、取消/重试、旧输入读取、图纸修改后的缓存失效与事务回滚必须保持。自动适配器的步骤数不能换算成 AutoCAD 秒数。

原图复测固定同一 DWG 副本、相同箱体/起始导线、配置及动作；首次读取、重复读取、首次导入、图内已有定义和已有实例分开计时。图面、保存重开与原生 UNDO 单独验收。当前不承诺固定秒数或提速比例。

真实样本定位按打开图纸的所属字典、固定块名、实例句柄、实际定义名及块表身份保存。每次使用仍通过 `handent`、`entget`、实体类型和有效名核对；样本删除、句柄复用、换图或实际定义改变时重新寻找，不能把历史句柄直接当作有效实例。

`WithTemplateScope` 只在同步准备、提交及生成调用内共享工作。每次模板复查仍读取完整块表头、实体及嵌套定义事实；事实完全相同且上下文有效时复用已计算的定义签名和已读取的动态属性允许值。属性名变化必须重新读取，文字样式和输出图层仍逐次检查；不缓存一个跨阶段的整体“模板有效”结论。

没有实例、只有定义时，在一次采集与校验范围内保持箱体和回路两个探针同时存活，复用它们完成校验后逐一清理，每块仅需一次临时插入。探针只登记在当前作用域，不进入长期样本缓存，返回模板不保留其已删除句柄。删除触发的 CAD 回调可能改变动态属性，即使普通几何 DXF 不变，也不能假定允许值没变；因此清理后丢弃动态证明，后续阶段需要时重新读取，不把旧允许值迁移到新的有效期。

保留输入、面板回调、未知检查回调、写入和原生放置的 `FreshBoundary`；手工选择模板状态也进入输入边界。保存草稿后的写入、原生放置后的定义/编号/源图核对及事务回读未跳过。同名同范围内部几何改变仍会被完整事实与签名核对拦截，不能用块名、范围或 DBMOD 替代。
