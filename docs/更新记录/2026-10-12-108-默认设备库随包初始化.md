# 108 默认设备库随包初始化

日期：2026-10-12
状态：511 项联合回归、Windows COM 及 108 包检查通过；真实 AutoCAD 2020 验收待执行

## 问题与结果

此前 49 项天正图形只放在独立的 `设备库-002` 中，插件交付包没有这些资产，也没有首次加载的补齐流程。另一台电脑的 Administrator 用户打开的是自己的空设备库，无法自动得到默认图例。工具进程中更新 Zyf 的本地缓存目录不能替代目标 CAD 用户的初始化。

108 将全部 49 项默认 DWG、SLD、索引和来源清单放进应急照明包。APPLOAD 加载包内 `START-CAD2020.lsp` 后，程序在当前 CAD 用户的活动设备库中自动补齐。第一次运行 `ELDEVLIB` 即有 1 个配电箱、48 个设备，可直接选择设备填写功率。默认功率为空，空功率不会当成 0W 或有效默认值。

## 保存与兼容

默认来源是正式仓库资源 `assets/default-device-library`，用户库继续使用已有目录设置，或当前用户的 `LOCALAPPDATA/Emergency-Lighting/device-library`。已有条目按完整图块名或精确别名匹配；保存过的功率、名称、别名、地面、启用和删除状态保留，只补缺项和缺失图形。用户自定义的完整图形保持原样。

默认资源目录设置 Git `-text` 属性，防止换行转换改变索引、来源清单和内嵌资源的字节；文件文本编码保持 UTF-8。暂存后逐项核对 101 个源资源与工作目录字节一致。

补齐过程在设备库写锁下创建新的不可变资产版本，并在所有复制成功后一次发布索引。复制失败时原索引保留，释放本次写锁，可重试。重复打开完整库不复制资产、不重写索引、不从 CAD 导出图形。初始化导致新设备编号变化时，窗口中未保存的新设备输入按名称重新关联；其他草稿换到空闲编号，原始输入保留。

备用本地运行目录的启动数据也包含同一批默认资产。二进制以 Base64 分片保存，写出后核对字节；UTF-8 索引保持原编码。实现依据为 [Microsoft MSXML nodeTypedValue](https://learn.microsoft.com/en-us/previous-versions/windows/desktop/ms762308%28v%3Dvs.85%29)。

“更改库目录”改用打开文件对话框，选择已有 `catalog.eld`；读取或目录设置失败时恢复设备库窗口并显示原因，保留当前库及输入。UTF-8 读取显式跳过 BOM 字节，并保留大小和编码校验错误，避免被泛化成 `quit / exit abort`。截图未提供具体文件和读取日志，现场仍须核实其原始失败原因。
