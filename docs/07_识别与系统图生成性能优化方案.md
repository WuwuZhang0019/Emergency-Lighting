# 识别与系统图生成性能优化方案

日期：2026-10-11
状态：分阶段实施中；根据 091 失败样例完成 P2 长字符串解码与实际读回复用首步，126 项联合检查通过；092 成功路径性能基线仍待采集

## 1. 目标与基线

在保持识别结果、实际功率、稳定回路身份、事务撤销和 DWG 回读校验不变的前提下，减少 ELSTAT 识别及点击“生成或更新”后的等待。已有有效系统图更新时只执行增量修改，未变化的回路和文字不重建、不重复写入。优先处理重复识别、增量更新和重复记录解码，并精简保存数据本身，缩短鼠标放置后的等待，再根据测量决定是否优化日志及首次采集。

最初制定方案时的基线为 `ca229a0`、交付包 059。该版本已包含原位更新后定位，以及删除旧系统图后重新放置。实施时应核对最新代码，保留后续修复与功能；历史 059 和当前版本分别计量，不混作同一基线。自动检查通过不代表全部真实 CAD 场景完成验收。

现有耗时来自 `ELTRACE-debug(10).log` 第二次运行，即 057 中四回路成功更新，不是 059 的性能基准：

| 阶段 | 日志耗时 | 含义 |
| --- | ---: | --- |
| RECOGNIZE_FIXED | 657 ms | 首次识别 |
| PRE_GENERATE_FRESH | 922 ms | 主面板确认后的源图复核 |
| CCKK2 | 5140 ms | 四回路更新入口整体 |
| TX_WRITE | 2469 ms | 包含于 CCKK2 的写入主体 |
| STORE_SERIALIZE | 281 ms | 写入主体内的编码 |
| STORE_PARSE | 766 ms | 写入主体内的写前解码校验 |
| STORE_READBACK | 1328 ms | 写入主体内的实际 DWG 回读与审计 |
| PANEL_DIALOG | 11094 ms | 包含用户阅读、输入和等待，不作为计算耗时 |

嵌套阶段不能相加。PRE_GENERATE_FRESH 与 CCKK2 顺序执行，约 6.06 秒只表示这两个已计时区间之和，不代表完整按钮耗时。首次插入的 CCKK2 还包含等待用户放置，不能直接与原位更新比较。

该四回路运行有四次 SPLIT_NETWORK：首次识别一次、生成相关复核三次；DWG 记录包含 12710 个字段。日志能够证明重复执行及已测耗时，但未单独测出每次 StoreRead、日志写盘和各几何步骤的成本。因此不承诺固定提速比例，先建立可重复基准。

另一个存储样例来自 `ELTRACE-debug(12).log` 与 `diagram-521504707(3).eld`，为五条实际回路、两条预留，不能与上述四回路直接比较。按现有编码规则重建主记录，13688 个字段的构成如下；字段包含结构标记、坐标分量、分段字符串，并不代表 13688 个图形对象。

| 数据类别 | 编码字段数 | 含义 |
| --- | ---: | --- |
| SOURCE-SIGNATURE | 5120 | 平面导线、设备及连接等源图快照的完整字符串表示，用于发现来源变化 |
| 三份模板数据 | 5364 | CONFIG 内 TEMPLATE、记录直属 TEMPLATE、全局 FIXED-TEMPLATE，各 1788 个字段 |
| PLAN、ROWS、CCKK-LABELS | 2546 | 系统图生成计划、回路行及关联文字等数据 |
| 其他字段及外层结构 | 658 | 功率配置、身份、版本、状态等 |
| 合计 | 13688 | 同时包含平面来源校验数据与系统图关联数据 |

模板重复两份的理论毛减量为 3576 个字段，约占样例总数 26.1%；新引用及版本信息仍有开销，这不是已实现的压缩率，也不是字节数或耗时的同比降幅。源图签名目前是完整序列化文本，不能把它当成一个短摘要字段。

该样例的 STORE_SERIALIZE、STORE_PARSE、STORE_REPLACE_PAYLOAD、STORE_READBACK 分别为 313、922、47、1203 ms，四个顺序阶段合计约 2.49 秒。CCKK2 总计 11.297 秒还包含鼠标拖放等待；现有日志不足以精确还原全部点击后耗时，不能直接认定收尾固定为 5 秒。P0 须补齐放置确认到命令可再次输入之间的计时。

## 2. 当前代码中的优化位置

| 位置 | 当前行为 | 优化方向 |
| --- | --- | --- |
| [diagram-commands.lsp](../src/diagram-commands.lsp) 的 EL:EditPanel | 面板确认后先复核源图，再进入生成；多处读取主记录 | 传递本次已取得的数据，避免相邻调用重复读取 |
| [diagram-update.lsp](../src/diagram-update.lsp) 的 EL:FreshResult、EL:SyncDiagram | FreshResult 调用完整 RecognizeFixed；同步入口和提交前再次复核 | 区分完整识别与变化检查，合并无交互、无源图写入区间内的重复工作 |
| 同文件的 EL:ApplyUpdate | 已按 UID 复用对象，部分属性有差异判断，但仍遍历全部行并对未变化对象调用图层设置 | 生成明确的增量操作清单，只对变化属性和受影响成员执行写操作 |
| [diagram-store.lsp](../src/diagram-store.lsp) 的 EL:CreateDiagram | 新图放置后再次检查源图 | 保留跨鼠标放置的检查，不能直接使用放置前缓存 |
| 同文件的 EL:StoreWrite、EL:StoreReadback | 写前编解码校验，写后审计 dictsearch/entget，再读取解码；调用方还会再次 StoreRead | 复用实际回读并校验过的数据，保留完整字段和精确比较 |
| [simple.lsp](../src/simple.lsp) 的 EL:SimpleCollect、EL:SimpleNetwork | 遍历模型空间候选、读取块范围、建立连接与断口关系 | 先减少重复调用；首次扫描仍慢时再优化候选及单次扫描内的几何复用 |
| [common.lsp](../src/common.lsp) 的 EL:LogAppend、EL:LogEvent | 每条落盘日志打开、写入、关闭文件；部分高频日志已有默认过滤 | 测量正常日志开销，优先减少重复明细，必要时小批量写入 |

EL:SourceCurrent 比较图纸、识别规则和快照签名。快照经过采集、网络处理及 EL:CircuitSnapshot 生成，不能假设 SimpleCollect 的原始数据与现有签名等价，更不能仅凭对象数量相同就判定源图未变化。

## 3. 必须保持的行为

- 仍按实际导线、设备及出线种子识别回路；数量、每回路功率、普通／地面状态、预留数量和文字结果一致。保留断口、歧义、环路、跨箱归属及既有几何检查。
- 稳定 `circuit-uid`、来源身份和关联所有权保持不变；不按行号、距离或功率猜测匹配，不改变天正原对象。
- 已有有效系统图只做增量原位更新，未变化实体保持句柄、属性和允许的人工位置，不以全部删除再生成代替更新。旧箱体已删除时才进入既有重建流程；残余对象只有通过所有权与可写性检查才清理，取消时能恢复。
- 保留源图变化保护、动态块允许值及写后回读、真实 TEXT 属性检查、写前编解码相等校验、写后 DWG 精确回读，以及 nil／异常两种失败撤销。
- 不通过截短签名、丢失必要信息、放宽数值容差或直接相信内存中的待写数据提速。允许无损去重、紧凑编码及经等价验证的派生数据重建；精确复核失败不得假报成功。
- 维持一个面板、无额外 Yes 确认、固定 mm、正常生成后定位；不能让用户额外选择“快速／安全”模式承担一致性判断。

## 4. 分阶段实施

### P0 建立历史版本与实施前版本的计时基线

先新增轻量性能计数与汇总，不改变识别和存储结果。计数器限定在一次顶层命令内，成功、取消和错误出口均输出一次汇总。

指标分为必要与按需两级，避免基线采集本身成为新的瓶颈：

- 必要指标：非交互程序总耗时、放置后收尾耗时、采集／建网／识别、存储提交及收尾主要阶段耗时，完整识别、StoreRead／解码、实体及主记录写入、日志落盘的调用次数，以及对象数、实际／预留回路数和存储字段数。优先使用命令内计数器，结束时统一汇总，不为每个对象增加落盘日志。
- 按需指标：快照／签名、回路追踪、写前编码／解码、实际回读、实体及文字创建、重生成／定位等细分耗时，日志文本构造与文件写入耗时，以及各类增量操作数和存储体积分解。主要阶段显示瓶颈后再开启对应明细。

嵌套阶段标明包含关系，不累计成虚假的总耗时。P0 的分级只控制初始测量成本：P1a 验收仍必须记录真实写接口调用和增量操作数，P2a 验收仍必须记录字段、字节及模板份数等数据量指标，不能以“按需”为由省略对应阶段的证据。

单独计量非交互更新的总耗时；首次放置分开记录等待鼠标与放置后的程序执行。新增放置确认、关联数据准备、源图复核、存储提交、诊断导出、定位和命令结束的时间点，单独报告“放置确认到命令可再次输入”的总耗时。面板停留、文件选择、人工回路核对不算性能收益。

按需开启详细存储统计时，同时记录逻辑业务数据量、编码字段数、实际序列化字节数、模板唯一版本数及重复份数、每次提交改写的记录数和字节数。字段少不等于字节一定少；DWG 文件大小受其他内容影响，只作辅助指标。按模板、源图快照、回路行、文字关联和其他元数据分别统计，定位体积来源；进入 P2a 前补齐该组基线。

P0 即加入正常业务日志开启／关闭的对照，在相同 DWG 状态和操作场景下测量，性能计数与最终汇总通过独立路径保留，不随业务日志一起关闭。先判断日志整体成本；若差异显著，再区分文本构造、格式化与文件打开／写入／关闭的成本，决定 P3 是否值得实施及采用何种方式。关闭业务日志仅用于测量，不改变交付默认保留关键诊断的要求；计时开销也应受控，不用逐事件落盘来测逐事件落盘。

产出：脱敏样例说明、机器／CAD 版本、必要指标汇总与按需明细、日志对照结果。根据主要开销、改动风险和依赖关系确定 P1、P1a、P2 的实施顺序；日志不足时先补计时，不直接删校验。

### P1 减少生成过程中的重复识别

先梳理 EL:EditPanel → EL:InvokeCCKK2 → EL:SyncDiagram → EL:CreateDiagram 的调用链，标出用户交互、原生命令、源图复核及写入边界。

实现顺序：

1. 把已取得的识别结果、快照及其适用范围显式传递给相邻调用，避免在同一受控区间重复执行完整识别。
2. 检查是否可以提取与现有签名严格等价的“新鲜度检查”路径，省去仅为比较签名而进行的回路遍历。先做新旧路径等价测试；若网络阶段会影响签名，继续保留该阶段。
3. 将真正的最新源图检查保留在写入前；首次放置、重建放置或其他用户交互之后仍重新检查。已有的配置、模板及输出对象预检继续执行。

当前 EL:SyncDiagram 两次 EL:FreshResult 之间可能发生人工排版冲突后的重排确认等交互，不能仅凭同一函数内调用两次就删除其中一次。分别标注有交互与无交互分支，只合并能够证明满足复用条件的路径；交互后的复核保留。

允许复用必须同时满足：同一 DWG 会话、同一来源配电箱、相同识别配置，且从取样到使用之间没有交互、外部命令、源图写入或未知回调。不能证明区间未变化时，走现有完整检查。

第一阶段不采用跨命令缓存，不只依赖 DBMOD、修改时间、对象数或一次“未变化”标志。UNDO/REDO、切图、重新加载、取消、异常、源图或配置变化全部失效；未来若引入事件驱动失效，须单独设计和验证。

完成条件：明确减少了完整识别调用次数；对几何、设备、出线及规则变化的拒绝能力不下降。缓存命中不是独立验收依据。

### P1a 已有系统图只执行增量更新

本阶段为必做项。“原位更新”只说明位置和关联保留，不能替代增量写入要求。复用当前 EL:ApplyUpdate 已有的差异处理，补足仍对未变对象设置图层、重复维护文字或写主记录的路径，不另建一套全图重绘流程。

以最近一次成功提交并回读验证的记录、当前实际输出实体和本次核对结果为依据，按来源配电箱身份与稳定 `circuit-uid` 比较。不能只比较行号、功率或旧记录中的文本；对象可能已被删除、替换或人工移动。生成含对象句柄、目标属性、变化原因和依赖关系的操作清单，分为新增、修改、删除、补回和不变，再统一预检和提交。

具体增量算法按以下步骤实现，复用 EL:ApplyUpdate 已有的差异处理。EL:DiagramUnchanged 当前返回整体布尔结果，可保留为汇总判断，但不能替代逐对象、逐属性的变化清单：

1. 按来源身份和稳定 UID 对齐旧记录与本次计划，区分新增、保留和移除的回路；身份歧义直接进入既有拦截流程，不猜测配对。
2. 解析并核验相关实体的实际句柄、存在性、归属和可写性，读取参与比较的实际属性；缺失对象按既有补回或重建规则处理，外来或被替换对象不能当作普通缺失对象覆盖。
3. 比较目标值与实体实际值，分别记录图层、动态状态、文字、位置及所有权数据的差异。旧记录用于身份、布局基准和业务内容比较，不能代替实体实际值；允许保留的人工偏移不以默认布局覆盖，结构变化冲突沿用确认规则。
4. 展开设备到回路、回路到功率文字、布局到随动文字及模板汇总字段的依赖，形成完整变化集合。无法证明影响范围时允许全量计算与校验，再生成增量写入清单。
5. 每项操作记录对象或待建对象身份、属性、前后值、变化原因及依赖，合并同一属性的重复操作，按创建、引用、移动和删除的实际依赖确定执行顺序；另外计算主记录业务内容是否变化。
6. 统一预检后，在同一事务内执行清单并精确回读；属性相同不调用写接口，实体与业务记录均无变化时不创建写入事务。复用差异结果生成整体判断，避免为整体布尔检查再做一套重复比较。

| 本次变化 | 允许执行的增量操作 | 必须保持的对象 |
| --- | --- | --- |
| 图形、功率、类型及保存数据均无变化 | 只复核并按需定位；不创建写入事务，不更新业务记录的时间戳 | 所有图块、文字和主记录零写入 |
| 仅某条回路功率变化 | 只改该条功率文字及相关记录；模板确有汇总字段时同步受影响汇总 | 箱体、其他回路、用途文字和预留不重复写入 |
| 修改共享设备单个功率 | 根据设备与回路依赖关系，重算并更新所有实际受影响回路 | 不含该设备类型且无其他依赖的回路不重算、不写图 |
| 仅普通／地面类型变化 | 只切换对应回路的动态状态及确实受该状态影响的属性 | 其他回路及未变文字保留 |
| 新增或删除回路 | 仅新建新增回路及其文字，或删除已核验归属的移除成员；更新受影响的排列和预留 | 未受影响成员保留句柄；不能用整组重建替代 |
| 行序或预留位置需要调整 | 只移动目标位置确实改变的现有成员及随动文字 | 位置未变化的对象不调用移动或属性写入 |
| 仅箱体容量变化 | 只更新箱体对应动态属性和相关记录 | 回路和未变文字不重建 |
| 单个功率或用途文字缺失 | 只补回缺失文字并登记关联 | 其余合法图块及文字保留 |

增量计算与增量写图分开实现：仅修改功率等输入时，使用已验证的设备到回路依赖关系重算受影响部分；导线、设备几何或连接关系变化时，重新识别受影响连通范围。影响范围无法证明完整时，允许全量读取、识别和校验，再对计算结果执行增量写图；不得为了宣称“增量”而漏查新接入支路或断口阻挡。该流程不引入未经 P1 失效规则保护的跨命令缓存。

只有前后属性不同才调用 `vla-put-*`、`vla-Move`、`entmod`、动态属性设置等写接口；相同图层、颜色、文字、位置及所有权数据不重复写。必要的所有权、动态状态、源图及 DWG 校验可以读取全体相关对象，读取范围不等于修改范围。

增量操作及相应主记录更新保持同一事务，失败撤销本次全部变化。主记录业务内容确实变化时合并为一次提交，其余系统图记录内容保持不变；完全无变化不写 XRecord。当前 EL_TYPED_V1 保存在单个 XRecord 中，逻辑增量仍可能需要完整编码、替换该记录并严格回读，这不代表图形全量更新，也不能宣称已实现存储字段级物理增量。记录拆分及物理增量写入按 P2a 的独立格式升级流程处理。

完整新建仅用于首次生成或旧箱体已删除的重建场景。身份歧义、关联失配或人工排版冲突沿用已有拦截和重排规则，不自动整图重建。模板或全局参数变更可以使多个对象进入变化集合，但每个写操作都要有实际属性差异依据。

完成条件：测试记录真实写接口调用；无变化时实体写入和主记录写入均为 0，仅改一条功率时其他回路的写入为 0，新增／删除时仅变化集合及必要的依赖对象发生修改。重复执行同一更新仍为零写入；未变对象的句柄、属性和允许保留的人工位置保持一致。不能仅凭视觉一致或“没有新增图块”判定增量验收通过。

### P2 减少主记录重复读取与解码

2026-10-11 实施进展：用户提供的 091 样例有 6 次 StoreRead，累计 16421 ms，其中解码 16264 ms；两次完整识别共 3734 ms。先实现长字符串分层拼接，避免逐段复制不断增长的签名；同时提取统一的 StoreReadEntry，在写后审计完成后直接解码实际 DWG 条目，省去第三次字典读取。保持 EL_TYPED_V1、32 字符分段、写前精确比较和两路实际 payload 校验。该步不引入命令间缓存，事务提交后的上下文复用仍待后续独立实施。详见 [092 现场分析与检查记录](更新记录/2026-10-11-存储解码优化-092.md)。

该现场因源图复核失败而未进入生成，且 091 未扣除错误 alert 的等待时间；117156 ms 总区间及 96140 ms“程序区间”不能用作成功生成的计算基线。下一包修正相关弹窗计量，重新采集成功路径。3176 次日志落盘尚无 LogsOff 对照，不能据此认定日志 I/O 是主瓶颈。

保留 EL:StoreWrite 的写前校验和写后完整回读；优先消除同一次成功提交后调用链内多余的 StoreRead。

拟采用显式操作上下文，区分“待写记录”“从 DWG 回读且已验证的记录”“事务已提交”。只有回读校验与提交都成功，后续逻辑才可以使用已验证记录。原 StoreWrite 返回 T、失败返回 nil／异常的调用契约应保持，新增辅助接口或上下文，不直接改变全部调用方的真值语义。

EL:StoreReadback 可在完成 dictsearch 与 entget 的 payload 审计后，复用其中已实际读取的数据进行一次解码；保留 StoreRead 原有格式、结构、身份及版本验证。若采用该方式，应将校验提取为共用函数，避免形成较弱的快速解码分支。

失效边界：任意主记录写入、事务失败、回滚、恢复遗留事务、取消、UNDO/REDO、切图或未知回调。不得在全局保留上一命令的“已验证记录”。重建清理前后也不能沿用旧实体存在性判断。

P2 本身不改 EL_TYPED_V1 格式，不与旧记录迁移混在同一提交；保存数据精简作为下述独立必做阶段 P2a，分别验证读取复用与体积变化的收益。

P2 与 P2a 保留独立阶段及提交边界：前者验证旧格式下读取与解码复用的正确性和收益，后者承担持久化格式、引用、迁移及兼容回退风险。可以提前共用校验函数和约定上下文接口，但不因共用存储代码而合并实施或验收。

### P2a 精简保存数据并缩短插入后收尾

本阶段不仅减少读取次数，还要减少必须编码、写入和回读的数据量。先列出旧字段到新字段或重建规则的一一映射，明确哪些是业务事实、哪些是重复副本、哪些是可重建结果，再确定新格式版本。不能直接删除看起来重复的字段。

#### 保存内容与去重规则

| 数据 | 精简方案 | 一致性边界 |
| --- | --- | --- |
| 模板 | 同一 DWG 内按不可变模板身份及版本只保存一份完整定义；配置和系统图记录保存引用，全局默认模板也保存引用 | 内容不同不能合并；旧系统图引用的模板必须保留，不能随默认模板切换。旧三份内容不一致时先报差异，不任意选一份覆盖 |
| 平面源图快照／长签名 | 比较紧凑的带类型结构与可交付的无损压缩表示，避免重复字段名、转义和大量小字符串分段；选择实际收益更好的实现 | 保留全部参与变化判断的信息、数值精度、识别规则版本及确定的排序；可还原为与旧快照等价的数据，不按距离、对象数或短摘要代替精确判断 |
| 生成计划 PLAN 与回路行 ROWS | 保留稳定 UID、实际功率、类型、来源绑定、实体关联、布局基准及人工偏移等必要信息；确能由这些数据和模板确定重建的计划内容不重复持久化 | 逐字段验证重建结果；不能因重算丢失人工排版、预留状态或恢复草稿所需信息。无法证明等价的字段先保留 |
| 功率、配置及文字关联 | 共享配置只保留权威值，关联以身份及句柄引用；通用默认值可以由有版本的规则补齐 | 保留每个对象的归属、文字角色、实际覆盖值及必要的恢复信息；区分缺省、空值与显式设置，不能将不同含义合并 |
| 调试派生明细 | 完整展开快照和重复诊断说明放入按需诊断导出，不作为正常主记录的多份副本 | 正常 DWG 主记录仍独立满足重开、精确复核、更新与恢复，不依赖外部 .eld 文件才能使用 |

源图摘要如用于快速判定差异或索引，仅作为预筛选；摘要相同仍需精确确认，不能只留一个短摘要后丢弃验证所需的数据。未知算法、解压或重建失败按校验失败处理，不接受为“源图未变”。精简源图数据不等于删减平面图上的导线、设备或天正属性。

字符串分段长度需要实测 AutoCAD 2020 XRecord 写入／回读限制和中文双字节边界，不能直接把现有分段常量调大后交付。数值仍使用精确的类型表示，不以固定小数位文本换取体积下降。若采用压缩算法，须证明加载依赖能随完整离线交付包提供、解码成本低于收益，并保留版本及损坏检测；没有收益时使用较简单的紧凑结构。

#### 存储增量与旧格式兼容

1. 先完成模板去重与紧凑表示，再根据测量将不可变模板池、每张系统图的可变记录和根索引拆分为独立 XRecord。记录拆分是物理增量写入的候选实现，应单独验证；不能把单记录整段替换称作字段级增量。
2. 已拆分时只编码和改写本次变化的记录，未变化模板、其他系统图和根索引不重复写；必要的完整读取与校验可以保留。引用变更、实体修改及记录写入属于同一可撤销事务，提交前验证所有引用完整，不留下半套新旧数据。
3. 读取端兼容现有支持的旧格式（包括 EL_TYPED_V1）和新版本。普通读取、加载或查看不偷偷迁移；首次有实际保存需求时，在事务内构造新记录、精确回读验证，再切换有效索引。迁移前保留一次可恢复的原始记录，不能每次保存都追加历史完整副本。
4. 迁移保持 drawing-uuid、diagram-id、circuit-uid、来源绑定和有效实体句柄不变；重复迁移幂等，失败、取消及 UNDO/REDO 后数据与图形状态一致。缺失模板引用、旧副本冲突或未知未来版本应明确拒绝写入，不能当作空记录覆盖。
5. 回退包仍须能读取已落盘的新格式；若必须降格式，提供经验证的无损转换与回读流程。不能将不认识新格式的旧程序直接用于已迁移 DWG，也不能要求用户删除记录重新生成来完成回退。

#### 鼠标放置后的必要工作与可移出工作

放置后仍需取得实际实体句柄、位置和动态状态，检查交互期间源图是否变化，提交关联记录并从 DWG 精确回读。这些步骤决定下次更新是否可靠，不能仅为提前恢复光标而省略或假报成功。

优化安排如下：

- 放置前完成模板校验、静态配置规范化、可确定的生成计划和不依赖最终句柄／位置的数据准备；放置后只补充实际结果。跨交互后重新复核源图和已失效的前置结果，不盲目复用旧数据。
- 放置后使用精简记录及 P2 已验证的读回结果，避免再做重复完整编码、读取或解析；关联保存成功后再宣告生成完成。
- 正常成功路径只写有界的关键日志、计数和耗时汇总；完整 .eld 导出改为用户主动诊断或错误诊断时执行，并限制自动错误导出的规模和次数。诊断导出失败不能覆盖业务错误，也不能让已成功提交的生成被误报为失败。
- 保留必要定位，合并重复重生成或视图操作；用已有命令行显示当前阶段，不增加 Yes 选择或弹窗。不将 AutoLISP／COM 写图工作随意挪到后台线程，不把未完成保存隐藏在“完成”提示后。

完成条件：记录实际字段数、字节数和模板份数下降，读回业务结果与旧格式等价；新建、增量更新、重开、迁移及回滚检查全部通过。另用相同五回路样例比较放置确认到命令就绪的中位耗时，分清源图复核、存储、导出和定位各自贡献。既有约 2.49 秒存储测量是优化依据，不是可直接全部消除的耗时；没有真实 CAD 数据前不承诺固定秒数。

### P3 降低正常日志开销

复用 P0 的默认日志开／关对照结果判断收益；此前阶段显著改变日志量时补测。关闭日志只用于对照测量，交付默认仍保留关键诊断。对照只证明日志整体成本，不单独证明文件开关是瓶颈，缓冲方案须有进一步细分测量依据。

优先减少正常路径中内容相同的重复明细，使用阶段耗时和计数汇总。错误、事务开始／提交／回滚、存储差异、输出对象检查及重建结果仍保留。

只有确认文件频繁开关是显著开销后，才引入有大小上限的小批量缓冲。错误出口、关键事务边界和命令结束必须刷新；日志写入失败不能覆盖原始错误或改变生成结果。测试取消与异常时的尾部记录，说明崩溃可能损失尚未刷新的普通明细。不要仅关闭日志后宣称生成算法更快。

### P4 根据基线决定是否优化首次采集

若 P0 证明首次 SimpleCollect／SimpleNetwork 是大型图纸上的主要瓶颈，再评估更精确的选择集过滤和一次扫描内的几何复用。

先排除不参与统计的导线图层，保持所有可能参与连接或阻挡断口的图块。不能仅按箱体距离或灯具名称裁剪候选；远处接入导线的设备、断口阻挡对象、新增对象都可能影响结果。

对每次候选过滤变更做新旧完整输出对比，覆盖远端支路、中段接触、断口和跨箱案例。收益不足则保留原采集器，不为少量时间引入长期维护负担。

真实 CAD 对比使用同一机器、同一 CAD 版本、同一 DWG 基线副本及相同日志等级。每个场景预热一次，再记录至少五次有效运行的中位数和范围；冷启动另记。每次恢复相同 DWG 状态，防止把“首次生成”与“无变化更新”混作一组。自动适配器耗时不能替代真实 CAD 耗时。

## 6. 实施顺序、交付与回退

先完成 P0 轻量基线及日志对照，再按实测收益、改动风险和依赖关系安排 P1、P1a、P2，默认参考顺序仍为 P1 → P1a → P2，但不固定。可以先处理 P1a 中未变对象仍设置图层等明确且局部的缺项；无条件写接口的数量不等于实际耗时，不能据此预先断言 P1a 比 P1 收益更大。提前实施的阶段必须具备自身所需的计量和正确性证据，每完成一阶段复测，再决定下一阶段。

P1a 增量更新与 P2a 保存数据精简仍为必做项，P2a 独立推进，并在复用 P2 读回结果前完成相应接口及验证。已有样例中的模板重复和存储耗时支持开展数据精简，但不能推导所有复杂方案都值得实施；无损压缩、物理记录拆分等候选方案由实际净收益和兼容成本决定，收益不足时采用更简单的紧凑结构。P3、P4 由测量决定；日志收益显著时可提前安排独立的 P3 修改。

实施前补充下列工作量与风险评估。以下是相对等级，不是工期承诺；P0 后按具体改动点、测试缺口和真实 CAD 验证安排估算开发与验证时间范围，并区分编码工时与等待实测的日历时间，不在拆解前给出精确天数。

| --- | --- | --- |
