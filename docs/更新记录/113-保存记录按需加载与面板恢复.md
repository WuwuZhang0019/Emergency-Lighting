# 113 保存记录按需加载与面板恢复
日期：2026-10-13
状态：代码及定向检查完成，真实 CAD 验收待执行

## 现场依据

用户提供 `ELPERF (5).log`、`ELTRACE-debug (24).log` 和 112 包截图。日志完整结束于 `COMMAND-FINISHED`。

- 首屏 `PANEL_HISTORY_READ` 用时 2375 ms，`PANEL_START_INIT` 用时 2453 ms。原实现先创建 DCL，再读取完整保存库，读取结束前面板不能交互。
- 列表初始化只选择记录行，没有打开记录，所以回路和图块仍为空。
- `HistoryOpen` 原实现总是调用 `RecognizeFixed`。本次日志中拾取箱体后的同一识别路径用时 10672 ms；打开历史记录也会重复执行这一整套采集与建网。
- 正式记录的 `rows` 仅保存编号、功率和输出图形信息，缺少每条回路的导线、设备成员。已有 `source-signature` 虽有源图快照，但没有回路成员映射，不能凭空恢复图例。

## 本次行为

1. ELSTAT 首屏不读取完整保存库。可以直接拾取箱体，或单击独立的“加载保存记录”。
2. 加载成功后自动打开第一条仍有来源箱体的固定记录，同时显示回路、功率和图块；无需再点击同一行。其他记录仍可单击切换。
3. 列表重绘使用本次会话已有数据，不反复读取整个 XRecord。“刷新保存记录”单独重读列表，保留当前功率和面板输入；缓存不跨本次 ELSTAT 或图纸使用。
4. 正式记录新增 `panel-circuits`，草稿保存自身的来源签名。新记录直接恢复完整内容，不运行源图采集、建网或拾取。
5. 旧正式记录第一次打开自动补齐回路成员，使用已保存的箱体句柄，无需重新拾取；本次命令内再次打开同一份记录可复用。保存或生成一次并保存 DWG 后，后续直接恢复。
6. 仅浏览保存记录后取消不写入 DWG、不把已生成记录标成待更新。切换时仍按原规则保护并保存当前草稿。

## 数据与检查边界

正式来源签名与草稿来源签名分别管理；同源草稿仅在完整签名精确相等时使用明确的 `formal-source` 引用，避免重复保存整份大快照。缺少旧草稿签名不能自动借用正式签名。

打开记录表示恢复保存时的状态。保存和生成前仍检查当前源图及回路编号；源图变更时不允许直接用旧快照写入。原有主记录编码、事务、双路径完整回读和回滚保持原流程。

旧记录即使图形没有变化，生成时仍会补齐一次回路成员；补齐后的无变化生成仍不重复写入。
