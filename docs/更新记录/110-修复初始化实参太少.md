# 110 修复初始化实参太少
日期：2026-10-12
状态：代码修复；自动检查与 Windows COM 检查通过，真实 CAD 验收待执行

## 现场证据与原因

109 的现场截图显示 `runtime-109/assets/default-device-library/assets/ELDEV1/1/block.dwg : 实参太少`。这不是写入权限不足。109 替换了 Base64 解码，但保留了无参数的 `ADODB.Stream.Open`，未修复该接口的调用参数问题；此前适配器接受任意数量参数，漏掉了这一边界。

检查本机 Windows ADODB 类型信息，`Open` 的 `cParams=5`、`cParamsOpt=0`，各参数带可选标记；`WriteText` 的 `cParams=2`、`cParamsOpt=0`，第二项带默认值。不能用 PowerShell 自动补默认值的成功，推断 Visual LISP 的省略参数调用也能成功。

## 修改

启动写入、设备库 UTF-8 读取与保存、图形文件字节读取、资产复制回读共 5 处 `Open` 均显式传入 `nil 0 -1 "" ""`，分别表示省略来源及 ADO 默认模式、打开选项、空用户名、空密码。`WriteText` 显式传入选项 `0`，保持原文本内容。

保留分片写入及字节回读；启动异常追加 `STREAM_OPEN`、`BINARY_WRITE`、`SAVE_TO_FILE` 或 `BINARY_READBACK` 阶段，以便区分后续故障。无用户数据迁移或清理操作。

参考 [Microsoft ADO Stream.Open 参数](https://learn.microsoft.com/zh-cn/office/client-developer/access/desktop-database-reference/open-method-ado-stream)。Windows COM 检查的来源占位使用 `Type.Missing`；PowerShell `$null` 不能冒充缺省 COM 参数。

- 聚焦检查：`python -X utf8 -m unittest test_root_init test_default_device_library test_device_library test_device_assets`，从 `tests` 目录运行。启动适配器拒绝缺少参数的 `Open`；索引读写及资产回读检查完整调用参数。
- Windows 实际 COM：`tools/check_default_library_com.ps1 -PackageNo 110`，验证完整参数调用、101 个种子文件（1784941 字节）的分片二进制回写，以及带 BOM、无 BOM 的 UTF-8 读取和 UTF-8 写入。记录见 [COM 检查](../../tests/evidence/2026-10-12-default-library-com-110.json)。这些检查没有执行 AutoLISP 原生绑定。
