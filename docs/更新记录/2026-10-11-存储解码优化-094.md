# 存储解码优化与 094 复测

日期：2026-10-11
状态：实现与自动检查完成，289 项针对检查通过；真实 CAD 验收待执行

## 现场依据

用户提供的 093 ELPERF 两次成功运行，STORE_DECODE 为 9 次／1798 ms 和 8 次／1811 ms，STORE_READ 均为 6 次。第一次包含旧格式迁移，第二次只把回路功率文字 20W 改为 49W；相应程序区间为 10016／9703 ms，生成后为 4609／4313 ms。092 样本 STORE_DECODE 为 8 次／954 ms；对象数量不同，该数据只能定位当前开销，不能当作严格同条件退化比例。

普通更新的八次解码由六次业务读取、一次写前当前记录核验和一次写后实际回读组成；首次迁移还要独立解码历史备份。写前 STORE_PARSE 的编解码精确比较另外保留，不与 STORE_DECODE 的调用数混淆。

## 实现

1. 当前顶层命令内，复用已实际读取、完整解码并通过 schema 校验的记录。每次命中仍核对当前字典归属、XRecord 身份以及 dictsearch／entget 两路完整 payload；原始数据不同、记录替换／删除、切图、失败或重入时不复用。每次命令独立编号，开始／结束清空候选，写入前及失败回滚清空；解码或核验期间回调发生变化时不得发布旧候选。
2. 写后仍强制解码实际 DWG 回读，经过完整业务及两路原始字段比较后才提供候选。不会拿拟保存的内存记录充当回读，不缓存源图或系统图实体属性。旧文本／EL_TYPED_V1 普通读取仍不迁移，原始备份继续独立解析校验。
3. 紧凑格式池大于 32 项时，一次建立每段 32 项的只读索引，引用通过两次较短 nth 查找。完整字符串、符号、模板及身份不变，引用越界、损坏 pool、未来版本和模板副本冲突仍拒绝；小池不增加索引。仍采用 EL_COMPACT_TYPED_V2，字段和模板数量不因本次优化而减少。
4. 增加 store-read-cache-hits／misses 计数，默认汇总也计时 STORE_CACHE_CHECK。新增核对的耗时有实际成本，性能结论必须结合 STORE_DECODE、STORE_CACHE_CHECK、STORE_READ、TX_WRITE 和 AFTER-SUBMIT 的程序时间；这些阶段有嵌套关系，不相加。

## 自动检查与计量边界

可复现命令：`python -X utf8 tests/run_store_decode_checks.py`。检查覆盖读取复用、两路差异、记录删除／替换、切图、UNDO／REDO 数据变化、输入／解码／提交回调、重入、跨命令、未来版本、损坏数据、失败撤销、迁移／降级及依赖的识别、增量更新、面板和启动流程。

已有全源码静态检查对独立编号模块 HLBN:Check 的 hlbn-failure 发生误报：此状态在 HLBN:Execute、HLPLBH、HLPLBHRECOVER 的调用方明确声明为局部变量，使用 AutoLISP 动态作用域传递。检查仅对这一明确绑定增加核验，同时要求上述调用方仍有声明；编号工具源码未修改，其余未声明赋值仍拒绝。

模型计量只报告解码调用数和 nth 的链表遍历工作量，不把 Python 主机耗时当作 AutoCAD 耗时。检查证据写入 tests/evidence/2026-10-11-performance-decode-094.json，不保存用户完整 DWG 或原始诊断数据。

最终 271 项存储与依赖流程联合检查通过，18 项 CAD 数据边界补充检查通过，共 289 项。新增的读取路径也验证每次缓存命中只各读一次 dictsearch、entget，避免额外重复读取字典。默认汇总记录原始核对耗时，不能把其新增开销隐藏在“命中”结论里。

模型记录连续六次业务读取只解码一次，五次复用且没有主记录写入；一次实际保存的 STORE_DECODE 为两次，另外保留一次 STORE_PARSE 写前编解码比较。669 项原子池、2662 个 body token 的模型中，原平坦原子引用查找需遍历 895960 个链表节点，分段后原子及模板引用合计 72747 个，约为前者的 8.12%；逻辑内容完全 equal。该数值仅说明引用查找工作量，不能当作完整解码或真实 CAD 耗时下降 91.88%。

## CAD 2020 验证

1. 在原 DWG 的副本测试。完整解压应急照明-094.zip，APPLOAD START-CAD2020.lsp，确认 v94。不要直接加载仓库 UTF-8 源码。
2. ELPERF 选择 LogsOn、Summary，保持 `(setq *EL:LogVerbose* nil)`。与 093 对照时使用相同等级，先预热一次，再恢复相同 DWG 状态做五次同样操作。
3. 修改只属于一条回路的设备功率，再生成。预期只修改该回路的功率文字，保持其他实体句柄、位置和属性；既有 V2 普通原位保存模型预期 STORE_DECODE 两次、STORE_PARSE 一次、STORE_READBACK 一次。首次旧格式迁移还需一次独立备份解码。其他实际记录变化、多次保存可增加次数，不为凑次数删校验。
4. 保持源图、功率、容量、类型和配置不变，连续生成两次。预期图形与数据未变化，incremental-operations、entity-write-attempts、master-write-attempts、transaction-starts 全部为 0；当前记录至少首次读取一次，后续读取可复用。
5. 每次业务变化后 UNDO、REDO，再更新；保存、关闭、重新打开 DWG，再 ELUPDATE 选择受管对象。内容、功率和关联应正确，没有陈旧数据或残留事务。已有迁移备份不重复创建，ELSTORELEGACY 仍转换当前完整记录。
6. 保留 ELPERF.log、ELTRACE-debug.log，重点反馈 STORE_DECODE、STORE_CACHE_CHECK、STORE_READ、程序总区间及生成后程序区间。若出现错误，附完整命令行；需要完整诊断副本时运行 ELDIAG。
