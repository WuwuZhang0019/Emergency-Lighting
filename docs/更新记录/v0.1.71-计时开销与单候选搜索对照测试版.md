# v0.1.71 计时开销与单候选搜索对照测试版

日期：2026-10-21
状态：本地测试版；原图同条件耗时、图面及原生CAD待测，未合并、未推送、未发布

## 加载与正常测试

完整解压 `应急照明-v0.1.71.zip`，使用APPLOAD加载根目录 **ELFULL71.lsp**，再输入 **ELFULL71**，确认命令行显示 `v0.1.71`。加载文件仅注册命令，执行命令后才初始化本版并打开面板；同一CAD会话也要使用本版新命令。

内部 `PACKAGE_NO=170`，自包含后备目录为 `%LOCALAPPDATA%/Emergency-Lighting/runtime-170/`，诊断标记为 `package-170.marker`。软件版本与内部目录分别管理；旧v0.1.70包、解压目录及runtime-169保留。CADTools安装菜单不更新，当前分支未合并、未推送、未发布。

供简体中文Windows AutoCAD 2020测试。交付包全部LISP/DCL使用严格GB2312无BOM；不要直接加载仓库UTF-8源码，也不要混用旧入口和新模块。

正常测试使用默认模式0即可：重新拾取F072箱体与四个起始端，检查识别、编号、功率与预览，再生成系统图。以下四模式对照仅用于隔离开销，不是正常使用的必做步骤。

## 本轮调整

| 调整 | 当前行为与保持条件 |
| --- | --- |
| 实体细分计时按需开启 | 默认关闭每实体原生DXF、图块边界、导线记录的起止读时钟，保留所有批次阶段计时和业务计数；明确诊断时可恢复详细路径 |
| 单候选首设备搜索 | 初始只有一个候选或二分中收敛为一个候选后，直接执行原精确判断，跳过该候选的额外范围构造与粗筛；32步二分、候选顺序、接触和首次设备边界规则保持，多候选粗筛仍保留 |
| 会话诊断模式 | 新增ELPERFAB，分别恢复两项旧方式，以相同输入比较结果和耗时；每轮开始冻结模式，运行中不允许切换 |

识别范围、几何容差、回路编号、设备归属及预览行为保持。默认关闭详细计时后，`source-native-dxf-ms`、`source-block-bounds-ms`、`source-wire-record-ms`的0表示**未测量**，不能解释成这些操作没有耗时。以 `source-read-profile-enabled=0/1` 与 `source-read-profile-clock-reads` 区分关闭和开启状态，阶段批次耗时继续记录。

## 可选同条件对照

`ELPERFAB` 使用会话模式，不写入图纸或识别参数。每次 `PerfStart` 将选择冻结为本轮模式；运行中不能切换。时间轴顶部以及 `recognition-compare-mode` 记录本轮值。该命令不替代 `ELPERF` 的 Summary、Detail和LogsOn开关；四轮需保持这些开关相同。

| 模式 | 实体细分计时 | 单候选范围粗筛 | 比较用途 |
| --- | --- | --- | --- |
| 0 | 关闭 | 跳过，直接原精判 | 优化默认基线 |
| 1 | 开启 | 跳过，直接原精判 | 与0比较细分计时开销 |
| 2 | 关闭 | 强制旧方式 | 与0比较单候选粗筛开销 |
| 3 | 开启 | 强制旧方式 | 同时恢复两项旧路径 |

模式3只模拟v0.1.70的这两项处理，不等于加载了整包v0.1.70，不能据此替代两个历史版本的完整比较。

1. 使用同一未改动的商业照明测试副本、F072箱体、相同四个起始端及方向、配置、设备库和图层范围。四轮保持相同识别及预览操作，并区分首次与重复识别。
2. APPLOAD加载并执行ELFULL71，完成初始化后关闭初始面板。
3. 运行 `ELPERFAB` 选择3，再运行 `ELSTAT`，重新拾取同箱同起点，识别后检查编号、功率和预览并退出。对照轮不生成系统图、不修改功率、不改动图纸。
4. 立即运行 `ELDIAG`，保留本轮完整 `ELDIAG-时间` 目录，确认资料中模式为3。不要只保留ELPERF或截图，不要先开始下一轮覆盖最近运行。
5. 依次用 `ELPERFAB` 选择1、2、0，各自重复相同ELSTAT识别、预览、退出和ELDIAG导出。保留四个独立目录并注明对应模式；命令行实际导出路径为准。
6. 比较1与0隔离实体细分计时，比较2与0隔离单候选粗筛，同时核对识别结果一致。若要观察会话缓存或轮次影响，可再倒序复测，仍保持同样操作和独立日志；不强制增加轮次。
7. 最后恢复模式0，再进行实际生成及图面验收，完成后另行导出完整诊断。不要在模式3结束后直接把详细计时结果当成默认性能。

## 编号、功率与图面验收

本轮原图对照预期：38个设备、4条实际回路、2条预留、总功率94W。当前ZE1／73W仍来自自动补最小空号，来源为 `auto`；ZE2、ZE3、ZE4各7W，仍读取导线 `linenum`。编号、设备、UID与功率应作为整条回路一起对应，不能交换功率或设备归属。

v0.1.70诊断中，平面可见ZE1位置的注记 `2227C` 关联值为0，其他关联注记也没有可读正文。本轮没有修复天正原生注记文字不可读；出现ZE1不能证明原生编号读取成功。需要恢复原生关联时，先保留诊断，再在测试副本中用天正重新标注并重新提取；程序不猜配邻近文字，也不自动重绑平面注记。

核对面板及系统图的编号与功率一致；查看全部回路时路径、颜色、设备归属和预览退出恢复保持。默认使用本图已有系统图块，实际生成时检查是否闪回、回路遗漏或功率错配。保存重开、原生Undo及必要Redo使用测试副本单独核对。

## 耗时口径与证据边界

历史原图识别：v0.1.69为22.782秒，v0.1.70为36.422秒，后者增加13.640秒。该结果是本轮处理计时开销和单候选搜索的依据；本版实际节省秒数仍待上述同条件原生CAD对照，不预先承诺提速。

原图v0.1.70记录了28474次额外细分时钟读取。默认关闭详细计时的目标是取消这些读取，同时保留批次耗时；操作次数减少不能直接换算为节省秒数。首设备单候选路径也须比较实际阶段耗时及完全相同的识别结果，不能只用少做范围计算认定整轮更快。

程序回归与交付包检查只证明对应程序及编码边界，不能替代真实CAD的耗时、天正对象读取、图面、预览、保存重开和Undo验收。
