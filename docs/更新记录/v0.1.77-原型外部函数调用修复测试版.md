# v0.1.77 原型外部函数调用修复测试版
日期：2026-10-22
状态：本地修复测试版；真实CAD接口与原图性能待复测，未合并、未推送、未发布

## 本次失败原因

v0.1.76拾取结束后报 `函数错误: ELNETCOLD76`。第一次握手把尚未注册的外部函数直接传给 `vl-catch-all-apply`，在目标解析处失败，没有进入预期的错误结果处理、NETLOAD或.NET计算。有限宿主之前未模拟catch目标解析与受保护函数体的区别。

`output (31).zip`包含APPLOAD及ELCOLD76两份时间轴、ELPERF和ELTRACE，共4文件，无原型JSON。总时间22.922秒，交互20.188秒、程序2.734秒；最后拾取结束到失败仅0.094秒。这些不是.NET计算耗时。本次是箱体2604F和五个起点，与历史F072四起点不同，不可直接作为同条件性能对照。

## 修复内容

用已定义的LISP函数包装健康握手与七参数业务调用，catch和PerfCall只接收封装函数；封装内部直接调用.NET入口。未加载时可捕获错误后NETLOAD，加载后仍须精确版本握手通过。新增握手开始、业务调用开始及桥接异常诊断，保留DLL加载路径与前后结果。

补齐 `COLD_NATIVE_LOAD`、`COLD_NATIVE_PROBE` 的默认粗计时白名单及中文标签。v76已有批次调用，但默认模式没有保留这两帧，本版修正。首次加载/JIT、桥接及写报告仍在最后拾取后的总计时中；每个新箱体重新读取、建树，不预热、不使用上次结果缓存。

新DLL/函数和命令使用77，内部176，旧v76包保持。C#只递增入口及程序集版本，候选算法不变；正式识别、编号和预览继续原路径。当前仍是.NET候选阶段原型，完整首次识别3秒目标尚未验收。

## 原图复测步骤

1. 新开AutoCAD会话，完整解压 `应急照明-v0.1.77.zip`，APPLOAD根目录 **ELCOLD77.lsp**，输入 **ELCOLD77**。
2. 默认 `Prototype`，先重新拾取本次箱体 `2604F` 及五个起点 `2606F / 260CD / 148A6 / 26060 / 26068`，保持方向、配置及图纸副本，Enter完成。
3. 正常应出现原型耗时和报告路径。每轮完成或失败后立即运行 **ELDIAG**，再开始下一轮；保留完整诊断压缩包，若失败也保留命令行文字。
4. 另测历史F072及四起点时单独留档，不和本次五起点混合对比。其他新箱体也每次独立采集建树。需要完整旧路径顺序参照时选 `Both`，它不构成严格冷A/B。

重点检查 `COLD_NATIVE_HANDSHAKE_BEGIN`及握手结果、`COLD_NATIVE_LOAD_BEGIN/RETURNED`、`COLD_NATIVE_PROBE_BEGIN`及失败记录、默认 `COLD_NATIVE_LOAD/PROBE` 两项计时，以及 `cold-probe.json`、`cold-comparison.eld`。握手成功只证明入口可调用，业务报告成功仍需继续验证；局部阶段低于3秒不能当作完整识别达标。

后备目录 `%LOCALAPPDATA%/Emergency-Lighting/runtime-176/`，标记 `package-176.marker`；找到完整交付目录时日志可能在解压包output，以命令行显示为准。正式面板入口为 **ELFULL77.lsp → ELFULL77**，旧runtime-175保留。

## 检查与验收边界

必要回归针对未注册目标在catch外解析失败、已定义封装内部错误可捕获、NETLOAD与精确握手、七参业务分派、桥接失败诊断、真实默认计时及独立入口。回归结果见下方证据，不以模拟通过代替AutoCAD实测。交付LISP/DCL继续由构建脚本严格转换为GB2312，并检查目录/ZIP和嵌入DLL一致；原生接口、实际秒数、包围盒和既有业务行为仍以原图报告为准。

本轮42项定向回归通过，耗时2.908秒：冷原型31项、冷入口8项、完整入口3项；包括真实默认计时及加载失败后的interrupted帧。证据：`tests/evidence/2026-10-22-v0.1.77-external-call-repair.json`。这些结果不替代原生CAD接口与原图性能验收。
