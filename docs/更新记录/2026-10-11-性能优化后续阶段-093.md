相邻复核通过显式操作作用域传递源快照。仅同图、同箱、同规则和同基准签名且无失效边界时复用；输入、原生放置、写接口、事务及临时模板探针都会失效。独立命令无跨命令缓存；失败、取消离开作用域后丢弃。提交前检查和跨交互后重采集仍保留。

检查：test_freshness_reuse、test_panel、test_fixed_source_signature、test_performance 共 29 项通过，包含真实分支/断口建网的新旧快照等价、输入与写入后失效、新增设备及规则变化拒绝。交付构建严格 GB2312 通过。实际减少调用次数和耗时以 093 的真实 ELPERF 为准。

## P1a 增量修改

按稳定回路 UID、实际实体句柄及属性计算操作清单，记录动作、前后值、原因与关联关系。只写变化的图层、动态属性、位置和文字；有效编号文字原位修改，保留句柄。无变化时不启动写事务、不写主记录。配置或功率记录单独变化仍会保存。

事务入口使操作样本失效，重新读取实际属性；写后只读核验所有受管成员及应删除对象，原生反应器造成意外变化时整组撤销。已有人工偏移、归属和锁层保护保留。

检查：15 项新增增量检查及 8 项既有更新检查通过，覆盖单功率、类型、容量、新增删除、人工偏移、锁层、归属冲突、业务记录单独变化以及事务与写接口回调。自动检查不代表真实 CAD 的动态块、撤销和反应器验证已完成。

## P2 提交后只解码一次

新增显式 TransactionVerifiedStore / TransactionVerifiedRead 返回已提交、两路完整回读核验的操作上下文。结束撤销组后，再核对字典归属、XRecord 句柄、类型以及 dictsearch / entget 的完整原生 payload。仅当前一次操作可复用已经解码的实际记录；失效、失败、跨操作或回调篡改时回到完整 StoreRead。StoreWrite 的 T 返回值和普通 Transaction 的业务返回保持兼容。

保存草稿与生成确认都使用该上下文。检查：12 项新检查及草稿/统计交接和源码契约共 41 项通过；再与全部增量及既有系统图更新检查共 60 项通过。包含 EndUndoMark 后回调篡改、归属变化、撤销失败、重入和不能仅凭 T 宣称保存。构建严格 GB2312 通过；原生撤销及重开 DWG 仍待 CAD 实测。

## P2a 紧凑存储、兼容与按需诊断

新线格式为 EL_COMPACT_TYPED_V2，逻辑记录仍为 schema-version 1。相同完整模板仅存一份，重复字符串／符号使用原值字典，结构使用整数 token；REAL 和 INT 仍由原生 DXF 40 / 90 保存，字符串仍使用原来的有界分段。完整内容决定身份，短键仅作查找预筛选；未知字段与高精度数值不丢弃。多个历史模板可以并存，同一记录中的模板副本冲突则拒绝写入。

读取兼容旧文本、EL_TYPED_V1 和新格式。普通读取不迁移，实际保存才转换；转换保留主 XRecord 句柄、绘图／系统图／回路身份及实体句柄，在同一事务内保留一次 EL_FIXED_V1_LEGACY 原始备份。已有备份核验后保留，不反复追加。未来版本、损坏引用、当前原生记录两路不一致或归属改变都拒绝覆盖。

ELSTORELEGACY 将当前完整逻辑记录无损写回 EL_TYPED_V1，并核验真实提交后格式；不把历史备份当作最新业务数据。正常成功路径停止完整 .eld 导出，显式 ELDIAG 只读校验原始受管对象后导出；诊断失败不改业务记录。

将用户完整 .eld 记录封装成含三份相同模板的 schema 1 主记录进行计量，旧格式 64418 个原生字段，新格式 42232 个，减少 34.44%；模板由三份合并为一份。字段内容字节估算由 608236 降至 435295，约减少 28.43%。估算按字段代码 2 字节、REAL 8、INT 4、GB2312 字符串字节数加终止字节计算，不是 DWG 物理文件大小，也不是现场主记录的实际耗时。compact / expand 及完整 native 编解码后与逻辑记录完全 equal。

暂不拆分物理 XRecord：先验证此紧凑结构的真实收益，避免增加多记录索引、迁移和回退复杂度。此阶段属于整段紧凑 payload 替换，不宣称字段级增量写盘。实体更新仍按 P1a 的属性差异执行。

## CAD 2020 验证步骤

### 1. 加载与测量准备

1. 复制原 DWG 留作基线；测试在副本中进行。完整解压应急照明-093.zip，APPLOAD 包内 START-CAD2020.lsp，确认命令行 v93。保留目录，不加载仓库 UTF-8 的 src 文件。
2. 输入 ELPERF，选择 LogsOn；再次输入 ELPERF，选择 Detail。默认日志明细保持 `(setq *EL:LogVerbose* nil)`。不同版本与不同场景使用同一日志等级。
3. 用你现有的五回路图执行 ELSTAT，核对箱号 ZZ-B1ALE(JZ)、5 条实际回路和 2 条预留。基线功率应为 90/20/20/20/20 W，预留不出现额外功率文字。生成、原位更新都应正常定位且无需再输回路数。

### 2. 正确性与增量验证

| 操作 | 应看到的结果 |
| --- | --- |
| 不改任何值再次生成或更新，连续两次 | 显示数据与图形均未变化；entity-write-attempts、master-write-attempts、transaction-starts、incremental-operations 为 0；句柄、人工位置不变 |
| 修改只属于一条回路的设备功率 | 只更新该回路功率文字并保存主记录；未受影响回路无写入。若设备功率按块名共享，多条关联回路应一起更新 |
| 单独修改回路类型，再单独修改箱容量 | 分别只改对应回路／箱体的动态属性；不重建未变实体、不增加预留功率文字 |
| 先手动移动一处功率文字，再改功率 | 文字内容更新，手动位置保留；结构改变时受影响的人工排版按已有确认规则处理 |
| 加入或移除出线后重新 ELSTAT，测试 2→4→2 | 数量及功率正确，只增删对应成员，保留其余有效 UID／句柄；预留行按实际数量调整 |
| 删除一处受管功率文字，再更新 | 仅补缺失文字，不重建其他回路；复制的外来文字不能被冒认 |
| 删除受管箱体后生成；鼠标放置时按 Esc，再重试 | 能重新放置；取消不留下本次新对象或半套关联，已有可恢复功率仍能使用 |
| 锁定输出所在图层后修改 | 清楚报告不可写，未错误宣告同步；解锁后可重试 |
| 每次成功变化后 UNDO，再 REDO | 图形、功率和 DWG 关联一起恢复，再次更新没有残留事务阻塞 |
| 保存、关闭、重开 DWG，再 ELUPDATE 选择受管成员 | 不依赖 .eld 副本仍能恢复功率、模板及关联并正确更新 |

源图变化可在成功统计后 MOVE 一段参与连接的导线，保留旧统计结果，运行 ELGEN 打开面板并点击“生成或更新”；应提示源图变化、要求重新统计，不按旧结果覆盖系统图。此拒绝测试前不要先 ELSTAT；拒绝后再 ELSTAT 重新识别，应采用新的连接结果。拖放期间外部反应器修改源图／模板的故障注入已有适配器检查，真实带反应器环境另行核验。

### 3. 迁移、诊断与旧包回退

1. 在尚未用 093 提交业务修改的 092 DWG 副本中运行 `(EL:StoreRead)` 或 ELDIAG，只读检查后以下表达式应仍显示 EL_TYPED_V1。不要用打开编辑面板后取消来证明只读：取消核对会标记原结果待更新，属于业务写入。

   `(cdr (assoc 300 (dictsearch (namedobjdict) "EL_FIXED_V1")))`

2. 修改一个实际值并保存，表达式应显示 EL_COMPACT_TYPED_V2；以下表达式应返回 T。重复保存仍只有这一份备份，受管实体身份不变。

   `(if (dictsearch (namedobjdict) "EL_FIXED_V1_LEGACY") T nil)`

3. 运行 ELDIAG，保存命令行给出的完整 .eld 路径。正常生成无需自动 .eld；把该副本删除或移走后，重开 DWG 的更新仍应成功。
4. 在另一个副本运行 ELSTORELEGACY，确认成功后检查 marker 为 EL_TYPED_V1、保存 DWG。重新打开并加载 092，原功率、句柄、模板与系统图关联应可读取。重新加载 093 后修改一项实际功率或类型，点击“生成或更新”，marker 应再次转为 V2，再保存 DWG；原始历史备份不被覆盖。仅 QSAVE 或无变化提交不会触发迁移。

### 4. 五次性能对照与反馈材料

首次生成、单功率修改、无变化更新分别成组，每组预热一次，恢复同一 DWG 状态后测至少五次。比较程序区间及 panel-submit 后的非交互区间；用户停留和等待点击不算程序加速，inclusive 阶段有重叠不能相加。

记录 recognize-fixed-calls、freshness-scan-calls、store-read-calls、store-context-reuses、store-payload-fields、store-template-pool-count、incremental-operations、entity-write-attempts、master-write-attempts、transaction-starts、log-write-attempts，以及 stages 中 STORE_DECODE 的次数与耗时。无变化场景应零写入，单功率场景应只影响依赖对象；实际识别调用、格式字段数与耗时以日志为准。

随后在同一场景用 ELPERF → LogsOff 做五次对照，再恢复 LogsOn。保留两组 ELPERF.log；默认日志减少不等于识别算法本身提速。093 与 092 对照须分别从未迁移的相同基线副本开始，不把首次迁移混入普通增量保存。

反馈材料：两份完整 ELPERF.log、ELTRACE-debug.log，运行 ELDIAG 主动导出的 .eld，以及出现错误时的完整命令行截图。现阶段自动检查和包检查能证明对应代码契约，尚未完成上述真实 AutoCAD 2020 验收。
