# v0.1.76 原型加载握手修复测试版
日期：2026-10-22
状态：本地修复测试版；真实CAD接口与原图性能待复测，未合并、未推送、未发布

## 本次失败原因

v0.1.75拾取四个起点后报 `no function definition: ELNETCOLD75`。旧就绪判断把 `atoms-family` 对未定义项返回的 `(nil)` 列表当作真值，跳过了NETLOAD；旧测试桩则用nil模拟未加载，漏掉这个区别。

`output (30).zip`只有3个共享日志，没有.NET原型报告，识别、采集、事务计数均0。本次23.688秒总时间包含11.437秒交互及拾取准备，不能作为.NET冷识别性能或3秒目标的证据。

## 修复内容

实际调用 `ELNETCOLD76` 的只读握手参数，校验精确版本回复；未就绪先NETLOAD，再握手，仍失败则在采集前停止。记录DLL路径、前后握手错误和加载阶段；原型返回的错误payload也保留到日志。握手不读取活动图纸、实体，不创建事务/索引或结果缓存；首次握手、JIT和NETLOAD仍在最后拾取后的计时中。

新DLL及函数使用76，内部175，避免与旧75程序集混用。正常识别、编号和预览算法保持。当前仍是.NET候选阶段原型，尚未完成.NET精确识别和编号迁移，不宣称完整首次识别3秒已达成。

## 原图复测步骤

1. 完整解压 `应急照明-v0.1.76.zip`。新开AutoCAD会话，APPLOAD根目录 **ELCOLD76.lsp**，输入 **ELCOLD76**。
2. 默认 `Prototype`，重新拾取F072及相同四个起点/方向，Enter完成。第一次.NET加载和握手计入本次耗时。
3. 正常应出现原型耗时和报告路径；随后换另一个新箱体测试，每次重新读取与建树。需要完整旧路径顺序参照时选 `Both`，它不构成严格冷A/B。
4. 每轮完成或失败后立即 **ELDIAG**，保留完整诊断压缩包。重点看 `COLD_NATIVE_HANDSHAKE`、`COLD_NATIVE_LOAD_BEGIN/RETURNED`、`COLD_NATIVE_LOAD/PROBE` 和 `cold-probe.json`、`cold-comparison.eld`。若仍失败，也保留NETLOAD附近的命令行文字。

后备目录 `%LOCALAPPDATA%/Emergency-Lighting/runtime-175/`，标记 `package-175.marker`；若找到完整交付目录，日志可能写入解压包output，以命令行显示为准。旧v0.1.75及runtime-174保留。正常面板入口为 **ELFULL76.lsp → ELFULL76**。
