# 148 自动导入系统图块与红色步骤

日期：2026-10-15
状态：实现与 46 项定向检查通过；交付编码及字节一致性检查见证据，真实 AutoCAD 2020 验收待执行

## 问题与修改

147 版提供了图块库文件入口并更换了系统块名，但生成路径仍只查询当前图纸。用户现场 ELSTAT 日志停在“未找到系统图块 ZYF_Tool_应急照明配电箱图块”，提示手动拷入，未执行自动导入。

148 版在模板采集前检查两个新块名和 `_TEL_DIM`、`ICDA-STYLE1`。缺少时用当前 CAD 主版本的 ObjectDBX 在后台打开随包 `templates/系统图块库.dwg`，先查全源定义，再分别向目标块表和文字样式表深复制缺项，最后读回目标表确认完整。块复制已带入的样式不重复复制；已有同名定义保留。随后使用原模板流程核对动态状态，不依靠随机旧块名、不覆盖已有块、不插入整个图块库的外层块。

CCKK、CCKK1 和单独 CCKK2 也复用同一导入入口。独立加载 CCKK.lsp 时，从已确认插件目录或支持路径定位图块库；主程序及本地内嵌运行目录均使用随包的原始 DWG。源 DWG 只读使用，成功或异常均释放 ObjectDBX，不切换活动图纸、不保存库图纸。复制异常可能保留已成功导入的定义，下次重试仅补齐缺项；不会产生临时图块实例或外层块。

文件缺失、源定义缺失、COM/深复制错误、目标表未读到所需定义时均明确失败并显示原因，不能将错误文本作为成功值。当前统计、功率和设备库未保存编辑保留。

第一步至第四步的编号及冒号改为红色，其后的操作说明和原按钮保持原样。DCL 原生标签不支持独立文字颜色，本轮采用对话框背景上的红色图像编号，按实际图像控件尺寸绘制；点阵内嵌在 LISP 中，运行时无需额外字体文件。`tools/build_step_labels.py` 可用本机宋体重新生成点阵。

实现依据：[Autodesk CopyObjects](https://help.autodesk.com/cloudhelp/2024/ESP/AutoCAD-LT-ActiveX-Reference/files/GUID-D9E0A89C-2D81-4141-8B88-B9AC6EAABD62.htm)、[Autodesk DCL 图像绘制](https://help.autodesk.com/cloudhelp/2025/ENU/AutoCAD-LT-AutoLISP/files/GUID-69540571-67D6-4389-B082-9B96FD048746.htm)。
