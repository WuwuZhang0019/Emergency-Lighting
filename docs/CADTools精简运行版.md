## 版本与构建

完整版版本以 `tools/build_cad2020.py` 的 `VERSION` 为唯一来源，精简版自动使用 `lite-v主版本.次版本.补丁号`，内部兼容编号仍取 `PACKAGE_NO`。新增运行模式不单独递增完整版版本，也不修改已交付的历史包。

## 本次独立测试

日期：2026-10-20
状态：按用户要求生成 lite-v0.1.62 测试包；实际 CAD 结果待反馈

1. 完整解压 `应急照明-lite-v0.1.62.zip`，保留全部目录。
2. 在 CAD 中用 `APPLOAD` 加载包根目录的 `ELTEST.lsp`，然后输入新命令 `ELTEST`。
3. 核对命令行显示 `ELTEST 使用 lite-v0.1.62` 和该测试包目录，再拾取原配电箱及回路。
4. 重点测试贴临图块及后续连线、加载提示次数、窄面板和展开面板的 Esc/叉叉退出。
5. 若仍漏识别，点击“导出诊断日志并打开文件夹”，保留这次资料及第一个漏识别位置。

`ELTEST.lsp` 在 APPLOAD 时只注册命令。`ELTEST` 每次从记录的测试目录重新加载 `src/load.lsp`，确认本版号、目录及就绪状态后才打开面板；CADTools 重新加载旧业务命令后再次输入 `ELTEST`，仍回到该测试包。目录无法确定时允许手动选择本包入口，取消或缺文件不会调用旧统计代码。原有命令仍保留；CADTools 菜单尚未同步到此版本。

测试命令只用于 Windows AutoCAD，使用交付包内已转为 GB2312 的文件。入口自身仍受 CAD 的信任设置约束，不保证完全没有首次安全提示。配置及手填数据继续使用下文约定的用户目录。

仅在明确要求打包时执行：

```powershell
python -X utf8 tools/build_cad2020.py --lite
```

输出 `output/应急照明-lite-v主版本.次版本.补丁号/` 和同名 ZIP；不会先生成完整版。目标已存在时停止，避免覆盖已有文件；重打包应先另行保留旧交付物，版本不因此递增。执行不带参数的原构建命令仍生成完整版。

## 保留与精简内容

- 保留全部业务 LISP、DCL、49 项默认设备图形和预览图、设备索引及原始系统图块库 DWG。
- 保留 `ELSTAT`、`ELDEVLIB`、`ELSETUP`、`ELPOWER`、`ELGEN`、`ELROOT`、`CCKK`、`CCKK1`、`CCKK2` 等现有命令；随包的独立批量编号模块也保留并加载。
- CADTools 的业务加载入口是 `src/load.lsp`。从 `v0.1.62` 起，入口内嵌同源转换后的模块代码，在目录及数据路径确认后按依赖顺序执行，不再逐个 `load` 业务文件；另附轻量的 `ELTEST.lsp` 供独立测试。模块文件仍保留用于诊断及完整性检查；不附带重复的 `START-CAD2020.lsp`、`UPDATE-序号.lsp`、`CCKK.lsp`。
- 不附带历史更新记录、开发文档、测试证据及测试图纸，仅保留本说明。
- 诊断导出的 PowerShell 内容沿用完整版的内嵌方式，仍按需执行；不再复制重复的外部脚本。
- 所有加载用 LISP/DCL 经共享转换流程严格编码为 GB2312、无 BOM；源码模板继续使用 UTF-8，不能直接交给 CAD2020 加载。

精简版仍是完整目录式运行模块，不能只复制入口文件。它不使用自解压备用资源，因此首次加载也需要全部运行文件齐全。

## CADTools 接入约定

建议将交付目录内容安装到 CADTools 的 `Contents/Tools/Emergency-Lighting/`。宿主从自身 DLL 的实际位置计算绝对目录，在目标图纸中设置 `*EL:CADToolsRoot*`，再加载该目录的 `src/load.lsp`。不要硬编码开发机路径。

下例中的路径为占位示例；必须使用生成后的 GB2312 文件，且安装目录符合 AutoCAD 既有可信路径设置：

```lisp
(setq *EL:CADToolsRoot* "C:/实际安装目录/Contents/Tools/Emergency-Lighting/")
(load (strcat *EL:CADToolsRoot* "src/load.lsp"))
(if *EL:MonitorLoadReady* (c:ELSTAT))
```

首次使用时在当前图纸中加载，后续入口按当前图纸的加载状态及精简版版本判断是否需要加载；切换或新建图纸不能只依赖 C# 进程级布尔值。检查 `*EL:MonitorLoadReady*` 后再调用目标命令，失败时显示加载错误。上述宿主菜单逻辑不属于本次实现范围。

`v0.1.62` 集成时还需同步 CADTools 宿主的版本常量及标记检查。本次按要求生成独立测试包，未修改宿主；不能仅改宿主版本常量就声称已升级。入口本身仍可能需要用户确认信任，本次不修改 `SECURELOAD` 或 `TRUSTEDPATHS`。

直接业务加载也可在 `APPLOAD` 中选择精简目录的 `src/load.lsp`；本次独立测试优先使用根目录 `ELTEST.lsp`。业务入口通过 APPLOAD 最近目录、当前精简版标记的支持路径、已记住的同版本目录定位。若宿主显式提供了错误目录，则直接失败，不自动切到另一份安装。目录不明时由宿主重新指定路径并加载；加载失败或成功后均可用 `ELROOT` 手动重新选择当前精简版目录。

2026-10-20 补充：首次加载失败也会注册 `ELROOT`，可修复路径后主动重新选择完整精简目录。注册表读取失败时继续查找其他有效候选；只有 `src` 位于支持路径时也能检查其完整父目录。尚未启动本轮监控时，不执行旧监控结束操作，保留 CAD 当前错误处理。

## 用户数据与升级

程序、默认设备资源和模板从安装目录只读加载。精简版的配置、功率输入、统计结果、性能日志和诊断资料使用：

```text
%LOCALAPPDATA%/Emergency-Lighting/CADTools/config/
%LOCALAPPDATA%/Emergency-Lighting/CADTools/output/
```

数据目录不带版本号，升级继续使用；安装和卸载程序不应删除该用户目录。启动只建立缺少的目录，不清空已有资料。

用户设备库沿用原有路径设置与默认功率初始化/升级规则，个人修改继续保留。完整版交付目录中的旧 `config` 不会自动搬迁或覆盖到精简版数据目录；需要沿用时应先备份，在关闭 CAD 后有选择地迁入。原有设备库导入、导出和旧功率导入命令继续保留。

同一张已打开图纸不建议混用完整版和精简版；切换发行模式时关闭并重新打开 CAD，避免共享命令及全局变量混用。
