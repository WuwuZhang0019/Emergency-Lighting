状态：实现完成；定向检查与交付检查见证据，真实 AutoCAD 验收待执行

## 现场证据

用户提供的 `output (13).zip` 包含 145 版的完整诊断资料。`export-error.txt` 记录 `stage: ZIP_LAUNCH`，原始错误是 `Automation 错误。未提供说明。`；`progress.log` 已完成 `ZIP_PREPARE` 和 `ZIP_ENCODE`，没有进程返回记录。关联核对通过，资料收集约 4.984 秒。

失败范围已缩小到创建 `WScript.Shell` 或调用其 `Run` 启动压缩进程，不能进一步断言是具体哪一个 COM 调用或操作系统设置。此前面板提示覆盖问题已修复，本轮不是显示旧错误。

## 修改

- 移除诊断压缩中的 `WScript.Shell` 创建和 `Run` 调用，改用 CAD 原生 `startapp` 启动隐藏的 PowerShell 进程；脚本继续内嵌，不在启动阶段释放 `.ps1`。
- 压缩器完成逐文件长度和 SHA256 核对、发布正式 ZIP 后，原子写入 `OK` 状态。调用端同时检查完成状态和非空 ZIP，启动成功不代表导出成功。压缩器错误写入 `bundle-error.txt` 并返回 `ERROR` 状态，面板完整失败信息仍写入 `export-error.txt`。
- 仅显式导出时按完成状态等待，完成立即结束，最长 30 秒。超时或取消时保留资料、写取消标记；压缩器发布前检查取消标记，避免已放弃的任务继续发布。等待结束或取消后恢复原 `CMDECHO`，计时支持 CAD 毫秒计数回绕。
- 进程启动后不再追加待压缩的进度文件，避免与压缩及文件校验同时写同一快照。快照目录和 ZIP 保持唯一名称，不覆盖旧包。
- 正常出图的放置与收尾流程不增加等待；导出按钮和可复制的 Windows 路径保持原有操作。

API 用法依据：[Autodesk startapp](https://help.autodesk.com/cloudhelp/2024/DEU/AutoCAD-MAC-AutoLISP-Reference/files/GUID-30EC493A-674B-4AAE-8C88-358E38CDAB21.htm)、[Autodesk DELAY](https://help.autodesk.com/cloudhelp/2016/ENU/AutoCAD-LT-MAC/files/GUID-C352A9F4-0057-43AD-9642-9BAA881224F8.htm)、[Microsoft powershell.exe](https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/about/about_powershell_exe?view=powershell-5.1)。
