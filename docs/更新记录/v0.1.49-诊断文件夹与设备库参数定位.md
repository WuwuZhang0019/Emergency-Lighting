# v0.1.49 诊断文件夹与设备库参数定位

日期：2026-10-15
状态：实现与 35 项定向检查通过；真实 AutoCAD 2020 验收待执行，本轮不打程序包

## 现场原因

用户提供的 `output (14).zip` 中，`progress.log` 显示全部资料文件已完成，`export-error.txt` 停在 `ZIP_LAUNCH STARTAPP`，原因是 `STARTAPP 未成功启动`。日志收集和压缩启动是两个阶段，本次移除默认导出流程对压缩启动的依赖。

同一资料的时间轴记录 `STORE_COMPACT_ERROR / TEMPLATE-COPY-CONFLICT`。已保存的四条记录均使用旧随机块名模板，记录内两份模板一致；当前 C900 是无输出的旧草稿。本次生成配置换成新块名后，SaveDraft 更新 config.template，却保留 record.template，下一次压缩编码按原有完整性规则拒绝这份冲突记录。此处的“压缩编码”是 DWG 记录编码，与诊断 ZIP 压缩是独立问题。

## 修改

- 诊断默认直接导出独立 `ELDIAG-<时间>` 文件夹。保留完整事件、时间轴、关联、保存记录、业务结果及逐文件检查点，manifest 明确 `export-format = directory`。默认不启动 PowerShell，不生成 ZIP，不等待压缩完成。目录名不覆盖旧资料，打开目录的反馈不覆盖导出结果。
- 用户可以直接发送目录内文件或自行压缩；资料收集或写出失败仍明确报错并保留已完成部分。旧的显式压缩辅助函数保留，但默认按钮与 ELDIAG 不再调用。
- 主面板与独立 ELDEVLIB 均增加“功率参数：catalog.eld”和“打开所在文件夹”。根据当前编辑库快照定位，并选中 catalog.eld；不自动保存设备。打开后保留功率、容量、设备名及其他未保存编辑。
- 设备库顶部路径、参数入口、图块库入口集中在固定高度的顶对齐区域，剩余空间供设备列表与资料编辑使用。依据：[Autodesk DCL 控件间距](https://help.autodesk.com/cloudhelp/2022/ENU/AutoCAD-AutoLISP/files/GUID-0118585E-596D-4EA2-BFE7-B0309CFEBFC7.htm)。
- 保存当前输入时，record.template 使用当前 cfg.template；从已有输出建立新草稿时也使用本次模板。仅更新当前箱体输入记录，其他箱体模板与旧图实体保留。原 CompactTemplates 的副本冲突校验不变，篡改副本继续拒绝。

## 默认功率反馈文件

只修改了设备功率、名称、别名、地面等参数时，逐项点击“保存设备”后，发送设备库目录下的 `catalog.eld`。默认位置为 `%LOCALAPPDATA%\Emergency-Lighting\device-library\catalog.eld`；切换过库目录时使用界面实际目录。

图形和图例在 `assets/`；仅功率反馈不需要附带。若新增或修改过设备图形、图例，则把 catalog.eld 与 assets 一起反馈。`history` 是历史备份，`.staging` 是临时图形，`recognition-preset.eld` 是识别配置，均不替代当前 catalog.eld。

本次用户尚未提供该参数文件，程序默认库功率不从回路合计反推；收到实际文件后再按设备名称及别名核对并纳入默认模板。
